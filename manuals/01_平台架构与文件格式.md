# 01 · 平台架构与文件格式

> 背景册（唯一必读）：理解数据在谁手里、文件长什么样——其余手册的规矩都由此推导。

## 一、两进程架构与数据主权

| 进程 | 持有 | 角色 |
|---|---|---|
| 游戏进程 | 实体、地形、关卡数据（.gil 全部非图内容）、玩法执行 | 关卡数据的持有者与裁决者 |
| 编辑器进程 | 节点图（且仅节点图） | 关卡会话内的图编辑器 |

两条关键实证结论 [J，2026-10]：

1. **编辑器进程内不存在实体数据模型**——广域对象图扫描证实所有疑似实体集合均为调试
   视图模型。实体操作只能走游戏侧通道（.gil 文件 / .gia 导入）。
2. **编辑器不读取 .gil 文件**——关卡数据由游戏侧在会话建立时推送给编辑器；
   .gil 是游戏侧的持久化格式。

**通道分域原则**（上述结论的直接推论）：不存在"改一个文件、全部内容热更新"的单一
干预点。图 / 实体+地形 各有数据归属，因此各有其交付通道（16 册）。

**数据流三视图**：.gil = 游戏侧视图；编辑器内存 = 会话视图；云端 = 权威存档。
本地存档目录（`%USERPROFILE%\AppData\LocalLow\miHoYo\<游戏名>\BeyondLocal\<账号>\`）
是文件级干预点，受"进入地图列表触发云端覆盖本地"定律约束。

## 二、容器格式（全部内容文件同族）

```
偏移 0    payload_total（大端 uint32）—— 硬性约束：= 文件大小 − 4
偏移 4    版本 = 1
偏移 8    魔数 = 806
偏移 12   类型码：1=.gip（玩家数据）/ 2=.gil（关卡）/ 3=.gia（资产组合包）
偏移 16   协议长度（= 载荷字节数）
偏移 20   protobuf 载荷
末 4 字节 尾饰 = 00 00 06 79
```

三条硬校验：魔数 / 尾饰 / payload_total。任一不满足即拒载 [A]。

**载荷特性——保序敏感的 protobuf 变体**：
- 字段序参与语义，必须原样保持
- **省略即默认**：省略字段 = 取默认值（不是"未写"，是"写了默认"）
- 因此读写必须走**保序解析树 + 最小修改 + 原样重编码**；常规"解析→对象→重序列化"
  会重排字段、补默认值，产物被拒
- 输出硬门槛：**往返一致性**（重新解析结果与输出字节一致，否则拒绝出件）[A]

本仓库的 `qxfmt` 工具链实现了上述读写纪律（见 QUICKSTART.md）。

## 三、文件族

| 扩展 | 类型码 | 内容 |
|---|---|---|
| .gil | 2 | 关卡主文件（实体区 f5 / 地形组 f7 / 图库 f10 / 脚本表 f50…全字段见 12 册） |
| .gis | —（806 容器） | 图分片（编辑器图工作文件；主 .gil 与分片双写） |
| .gia | 3 | 资产组合包（实体打包交付，15 册） |
| .gip | 1 | 玩家/会话数据 |
| .gir | — | 已发布关卡运行时数据 |
| .gilh | —（806 容器） | 地图级实体索引缓存 |
| .gils | — | 独立文件族（12 册） |

## 四、guid 段位总表 [A]

| 段 | 用途 |
|---|---|
| 0x400 | 路径 |
| 0x404 | 机关/gadget（实体合成主用段） |
| 0x408 | 怪物实体 + 客户端图 |
| 0x40c | 系统对象 |
| 0x414 | 关卡实体（合成时避开） |
| 0x40000000 | 图 guid（取空段号，分配前全档扫描） |
| 0x4000 段 | 客户端脚本 ID 域 |

段位错误的表现：实体不渲染、图不装载——无提示。

# 22 · 方法与经验（附录）

> 附录册：本项目逆向研究的方法论与教训——供同类格式研究参考。

## 一、七条元律（全部来自真实翻案）

| 律 | 内容 |
|---|---|
| 1 上下文限定律 | 每条结论必须记住成立的通道/版本/前提 |
| 2 推理绿 ≠ 实证绿 | 归纳法对新构造不完备 |
| 3 单样本不定常量 | 两个样本或一次导入回合才定案 |
| 4 跨版本禁外推 | 假设先过自家存档对照 |
| 5 拼装 ≠ 同源 | 拼装件的偏差即嫌疑 |
| 6 分层判定律 | 先判问题属于哪层：**编辑器/客户端层 → 读代码**（反编译，测试没有必要）；
  **服务器层 → 三角定位**（官方示例+社区+实测）；**视觉层 → 使用者的眼睛** |
| 7 静默降级律 | 编辑器/导入器/运行时对内容问题**全部静默**——错误唯一表达
  ="东西不见了"；对策：以编辑器实际行为为唯一裁判 |

## 二、核心方法（可迁移）

1. **以编辑器产物为参考实现**——不重新发明格式：对手方产出的结构天然合法，
   修改面越小风险越低；工具只承担"改对位置"的责任
2. **以编辑器行为为校验器**——无文档约束的环境里，装载行为是唯一权威；
   差分实验/负向测试/重保存对比三法把行为转译为规则
3. **先建判定，后建生产**——规则先行让生产线自带可解释的质量门
4. **判定体系必须测绘自身权限边界**——知道自己不能判什么，与能判什么同等重要
5. **故障注入是对抗静默失效的标准手段**——无错误信息的系统，拒绝边界即规则
6. **分域而治**——架构发现（数据主权分家）先于通道设计；没有万能通道
7. **勘误文化**——判例可翻案、里程碑可自我纠正，全部记录在案

## 三、流程教训（协作代价换来的定规）

1. **先验证后量产**：一个实体先进游戏看一眼，再谈两百件——本项目曾有一批 258 件
   建立在两个未验证假设上（旋转单位/坐标映射），返工三连
2. **逐区域小批量**（≤30 件/区）+ 目检反馈后再进下一区
3. **自动修复 ≤2 轮必停**，交人看——连续多轮不可见迭代会摧毁协作信任
4. **目检是最高效的判例来源**——旋转失效/穿模/地形虚空三个大问题均由使用者一眼
   发现；人负责"不对劲"，工具负责"为什么"
5. **产出与验证分开记账**——"写了什么"与"跑通了没有"是两个维度，只记前者会掩盖
   后者的空白
6. **先查自己的库**——旋转单位答案早就写在字段名（yaw_deg）里

## 四、人-机分工

程序负责产出与迭代，人负责创意、审美与验收。本项目 19 天的运行方式是这套分工的
实验记录。诚实结论：**验收环节不可自动化也不应自动化**——目检判例的价值反复被证明。

## 五、能力与边界（本项目自评）

已验证：格式全栈解读 / 静态内容产出（图·地形·实体）/ 三层质量闭环 / 双交付通道
（文件级 + .gia 官方导入）/ 数据五库。

部分验证：客户端脚本通道（最小闭环已证；量产路径为开放问题）。

开放问题：脚本量产挂载 / 俯仰旋转 / 同 guid 重复导入 / 水域通行与碰撞效果 /
包件数上限——每条均有最小验证方案待执行。

# 20 · 制作流程手册

> 流程册：从零做一张关卡的全流程。核心思想：**分解的判据不是功能，而是"一个合理的
> 测试范围"——拆到一次目检能看完、一轮反馈能改完为止。**

## 一、四层分解树（每层有验收点）

```
L0 作品设计   一页草图：各区功能与通道 + 玩法架构 + 绑定表（实体↔图↔Lua 谁连谁）
              验收点 = 用户确认草图（唯一全局决策点，此后不做大改）
L1 区域设计   地图划分区域；每区 ≤30 实体
              验收点 = 逐区目检（试玩中看位置/审美/穿模/氛围）
L2 测试单元   组件（门/桥/坡，参数化）/ 组团（一小簇实体）
              验收点 = 组件陈列室（空图+编号立牌，散步式逐件批准）
L3 管线设计   每单元：产出（合成+审计）→ 交付（按域选通道）→ 验证（三层+日志）
              验收点 = 离线校验绿 + 运行时证据
```

**层间纪律**：上游锁定再动下游；每层产物自带验收证据；**失败不跨层传播**（组件不过
只迭代组件，区域不好只改该区）。

## 二、测试范围四判据

| 判据 | 含义 |
|---|---|
| 可看完 | 一次目检覆盖该单元全部验收点 |
| 可归因 | 单变量——出问题差分能定位到该单元 |
| 可回滚 | 分区打包，一包失败不污染已验收区 |
| 可复现 | 设计文档可一键重建（解析→合成→打包管线） |

经验值：实体区 ≤30 件；陈列室一轮 ≤8 组件；自动修复 ≤2 轮必停交人看。

## 三、全流程操作序

```
① 前置判例（使用者在场一次批量判完开放问题）
   Lua 量产挂载 / 俯仰旋转 / 同 guid 重导 / 水域通行+碰撞效果 / 包件数上限
② 组件陈列室（结构类组件首展：门/桥/坡各变体）
   空图+编号立牌+一包 .gia → 使用者散步逐件批准 → 组件定版（参数化+尺寸档案）
③ 合流草图（L0）：场景（组件名拼装）+ 玩法架构（图/Lua 分工）+ 绑定表
④ 逐区域落地（L1-L3）：每区一轮——
   实体(.gia 分区包) + 图(模板组装) + Lua(14 册配方) 同轮交付
   → 日志基线 → 使用者试玩 → 差分 → 反馈 → 修复 ≤2 轮必停
⑤ 盖帽验收：全部能力在同一张图上跑通的完整作品
```

## 四、三条配套原则

1. **先验证后量产**：任何新面（新组件类型/新通道/新机制）先用一个最小测试单元进
   游戏验证，再批量
2. **组件先于场景**：结构类内容先在陈列室定版为参数化组件；场景文档只写组件调用
   与自由件，不出现裸结构坐标
3. **验收嵌入试玩**：每次试玩三重验收（区域目检/组件外观/运行时行为），前后日志
   基线夹持——把昂贵的人工操作榨干

## 五、双语分工速查（做什么用什么写）

| 内容 | 载体 | 手册 |
|---|---|---|
| UI 渲染/2D 玩法/交互采集/动画 | 客户端 Lua | 14 |
| 权威状态机/变量写入/世界与实体操控 | 服务器节点图 | 04 |
| 静态配置（AI/战斗/模型） | 实体参数 | 02 |
| 怪物自定义 AI | 客户端图挂复杂造物 | 04+02 |

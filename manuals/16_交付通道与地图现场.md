# 16 · 交付通道与地图现场

> 任务：把产出的内容送进游戏（选通道），并管理地图的本地/云端状态。

## 一、通道选择（架构决定的分工）

| 要交付什么 | 通道 | 详见 |
|---|---|---|
| 实体（批量布景） | **.gia 官方导入**（主力） | 15 册 |
| 地形 / 关卡数据 / 实体微调 | **本地文件修改**（本册 §二） | — |
| 图 | .gis 官方导入 / 模板产出 | 04 册 |
| Lua 日常迭代 | 活文件替换（外部社区方案可参考） | 14 册 |

没有万能通道——数据主权分家的架构结论（01 册）。
（项目内部另有进程内研究通道用于图域快速验证，不随本仓库发布——见 README 范围声明。）

## 二、本地文件修改协议

本地存档位置：`%USERPROFILE%\AppData\LocalLow\miHoYo\<游戏目录>\BeyondLocal\<账号>\
Beyond_Local_Save_Level\<地图ID>\<地图ID>.gil`（同目录含 external_lua_file\ 与 Temp 副本）。

```
① 确认编辑器已关闭（硬前提——运行中写入会被锁或被覆盖）
② 备份目标 .gil（时间戳副本）
③ 增量修改（保序树 + 往返一致性校验，见 01 册 §二）
④ 回读验证（实体数/地形块数/关键字段抽查）
⑤ 用户重进关卡 → 装载 → 目检
```

## 三、地图现场管理

**状态定律**（实测判例）：

| 定律 | 内容 | 操作含义 |
|---|---|---|
| 云端权威 | 编辑器保存 = 上行云端 | 修改本地后需在编辑器内保存一次，把修改推上云 |
| 列表覆盖 | 进地图列表触发云端覆盖本地 | 本地修改后避免无谓地重进列表 |
| 主件滞后 | 编辑器打开中的关卡主 .gil 非最新，**Temp 副本才新鲜** | 查询关卡状态双查主件 + Temp |
| 导入直写 | .gia 导入直接入云端 | 导入后无需再保存 |

**云端/本地分叉处置**：本地已改好而云端是旧态时——用户进编辑器（拉下云端）→ 关闭 →
重新应用本地修改 → 再进 → 保存（推上云）。若云端残留错误内容（如误导入），撤销 =
编辑器内删除，或以正确版本覆盖后保存。

## 四、通道行为速查（判例）

| 行为 | 结论 |
|---|---|
| .gis 图件 | 走编辑器官方导入 |
| .gia 组合包 | 走游戏内导入（编辑器内导入不了） |
| 版本 | 出件必须 CNRELWin7.1.0（旧版触发导入升级器重写） |
| 图头 | field1=10000 |
| 撤销 | 均无官方撤销；重复导入同 guid 的行为未验证（开放问题——决定迭代是
  小步重导还是先删后导） |

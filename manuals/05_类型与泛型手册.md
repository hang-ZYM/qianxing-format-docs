# 05 · 类型与泛型手册

> 任务：查类型码 → 实例化泛型节点 → 查枚举值。构图与校验操作见 04 节点图手册，本册只管类型与枚举层。

## 一、结构定律

### 1.1 ServerTypeId（服务器逻辑类型）[P+A]

29 个码位（ID 19 缺号疑保留），编号系早期逐步追加的历史产物，**无规律可推，必须查表**：

| 码 | 类型 | 码 | 类型 | 码 | 类型 |
|---|---|---|---|---|---|
| 0 | Unknown | 10 | FloatList | 20 | Config |
| 1 | Entity | 11 | StringList | 21 | Prefab |
| 2 | GUID | 12 | Vector | 22 | ConfigList |
| 3 | Int | 13 | EntityList | 23 | PrefabList |
| 4 | Bool | 14 | EnumItem | 24 | FactionList |
| 5 | Float | 15 | VectorList | 25 | Struct |
| 6 | String | 16 | LocalVarRef（Loc） | 26 | StructList |
| 7 | GuidList | 17 | Faction | 27 | Dict |
| 8 | IntList | 18 | EnumList | 28 | VarSnapshotRef（Vss） |
| 9 | BoolList | 19 | *（缺号）* | | |

### 1.2 ClientTypeId（客户端表现类型）[P]
后期独立设计，编号规整——**列表型 = 基型 + 1**：Entity 1/2｜Int 3/4｜Bool 5/6｜Float 7/8｜String
9/10｜Vector 11/12｜Enum 13（EnumList 17）｜Guid 14/15｜Faction 16（无列表对）｜Config/Prefab 族
18-21｜LocalVar 22（仅客户端）。Types 表 **ClientID=None 五行**（`L<Fct>`/`S<>`/`L<S<>>`/
`D<Unk,Unk>`/`Vss`——列表/结构/字典/快照族无客户端码）。类型定义消息以 `f1 = backend`（1=Server，
2=Client）区分两套体系；ServerType 另带 `impl`（0=primitive/1=struct/2=pair）与绑定 f100/f101 [P]。

**两套 ID 的正确关系（勘误）**[A，对源复核 2026-10-04]：节点目录 `Types.ID` 即 1.1 表
ServerTypeId（Int=3、Vector=12、Struct=25 逐值对齐）；docs/09 原表"ServerID"列实为 `BaseTypeID`
（基类型镜像，如 Int 行显示 2），**列名错挂待修**——查服务器类型码认 1.1 表或 data.json 的 ID 字段。

### 1.3 类型代数（节点目录字符串型）[C]
```
基本型: Int Flt Bol Str Vec Gid Ety Pfb Fct Cfg Vss Loc
容器:   L<X> 列表   D<K,V> 字典   S<...> 结构体   E<四字码> 枚举
泛型:   R<T> 单参数泛型   R<K>/R<V> 字典键/值泛型   L<R<T>> 嵌套泛型
```
数据引脚 2314 个中使用最多：Entity 370 / Int 332 / Float 303 / **R<T> 214** / Bool 190 / Vector 184 [C]。

### 1.4 泛型五件套 [J]（本册核心操作知识）
80 个泛型节点共 **3252 个实例化重载（Variants）**，每个 Variant 声明
`{Constraints:"C<T:Int>", KernelID, InjectedContents:[{pin 标识, TypeSelectorIndex}]}`——把泛型节点实例化为具体类型 T，需**同时改五处**：

1. `kernel_ref.runtime_id` ← Variants[i].KernelID（shell_ref 不动）
2. R<T> 引脚的 f4 类型码 ← T 的 ServerTypeId（查 1.1 表）
3. 引脚 TypedValue 内 type_def 的 tag 同步替换
4. `val_poly.chosen_type_index` ← TypeSelectorIndex（默认 0 可省略）
5. 值 storage 字段按 T 转换（int→float 时 f102→f104，且必须是包裹消息）

**值随型走**：带值引脚换型只改 1-4 不改 5，编辑器保存时会把值丢掉（规范化）[J]。

## 二、速查

**高频 ServerTypeId**：3 Int｜1 Entity｜5 Float｜4 Bool｜12 Vector｜6 String｜2 GUID｜25 Struct｜27 Dict｜16 LocalVarRef

**枚举体系**：**94 枚举类型**（一处 ID 撞号待复核，或为 93）/ 274 枚举值 [C]；Server 46 / Client 48。
标识符四字码，**C 前缀 = 客户端版**（BOOL/CBOL、REAC/CERE）；TypeID 段位 Server 10000+ / Client 210000+。
常用四字码：BOOL 布尔｜OCMP 比较(5)｜ELMT 元素(8)｜ENTY 实体类型(5)｜REAC 元素反应(声明 22)｜
SLOT 技能槽(20)｜HITP 打击表现级(11)｜TGTT 目标类型(8)｜GMOD 玩法模式(3)｜ITMC 物品变更(8)。
**枚举值 ID 分段**（Enums 表，段距≈100）：0-1 布尔｜100+ 比较｜200+ 逻辑｜1800+ 装置｜
4700+ 元素反应｜4900+ 物品变更｜5000+ 扫描｜5400+ 弹字｜5700+ 玩法｜5800+ 输入｜1000000+ 过滤

**节点目录统计**[A，对源重算 2026-10-04]：558 节点 = Fixed 478 + 泛型 80；Server 434 / Client 124；
引脚：流 510（入 219/出 291）、数据 2314（入 1679/出 635）；域分布 Execution 203 / Query 174 /
Arithmetic 101 / Trigger 57 / Hidden 17 / Control 3 / **Others 3**，合计 558 ✓（既有卷宗分项曾漏
Others 域致 555，此处对源重算闭合，勘误待回写）。

## 三、使用配方

**配方 A：泛型节点实例化（五步落地）**：① data.json `Nodes` 表按 Identifier 定位泛型节点，读 Variants；
② 按 Constraints（如 `C<T:Int>`）选覆盖目标 T 的 Variant；③ 按 1.4 五件套逐处修改；④ 泛型槽位值
必须包 poly 信封（铁律，详见 04 册——裸形态被装载层静默丢）；⑤ 产出后过校验链
`python -m qxfmt verify`（`--catalog` 传入节点目录可启用泛型槽裸值检查）；泛型入口/出口的
批量专项检查工具由项目内部维护，不在本仓库。

**配方 B：查枚举值**：四字码 → `EnumTypes`（按 Identifier 查，得 TypeID/System/Collection 成员清单）→
`Enums` 表按 `类别.成员` 标识符查（如 `ElementReaction.AGGRAVATE`）→ 拿值 ID 写入引脚 TypedValue。
**配方 C：查类型码**：服务器侧查 1.1 表或 `Types.ID`；客户端侧查 `Types.ClientID`；字符串代数查 `Types.Identifier`。

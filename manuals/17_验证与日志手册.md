# 17 · 验证与日志手册

> 任务：验证产出合法性（三层闭环）+ 读运行时证据（日志观察面）+ 一次试玩榨干信息。

## 一、三层质量闭环

```
① 写入自校验   输出后立即重解析，字节必须一致；头部三重断言
              （每次写文件自动执行——拦"结构写坏"；qxfmt 内建）
② 规则校验     已积累实证规则的离线检查
              python -m qxfmt verify <file>   （kind5 正典/信封/基本形态）
③ 编辑器终审   装载行为为最终裁决——导入观察 + 重保存字节对比
```

离线权限边界（本项目判定体系的重要成果）：幽灵 kernel / 报文截断 / 重复 ID /
极端坐标四类异常离线全 PASS——**只有活体装载有裁决权**。"verify 通过"≠"装载通过"。

**重保存对比法**：让编辑器装载后重新保存，对输出与提交做字节级对比——每处差异都是
装载器强制执行的未成文规则。这是格式规则研究的主要方法之一（docs/06）。

## 二、日志观察面（位置固定）

以下为默认安装路径（`%USERPROFILE%` = 当前用户目录；`<游戏目录>`/`<账号>` 按本机替换）：

| # | 观察面 | 位置 | 判读 |
|---|---|---|---|
| 1 | 游戏客户端日志 | `AppData\LocalLow\miHoYo\<游戏目录>\output_log.txt` | 试玩开跑信号 `SetCurLevelData...isTrial:True`；BOM 警告；**每次游戏启动重写**（增量分析先存基线） |
| 2 | Lua 脚本日志 | `BeyondLocal\<账号>\Beyond_Debug_Log\*.gia` | print/printerr 全量；一局一文件、试玩结束落盘；**无新文件 = 脚本未执行或无输出** |
| 3 | 节点图执行日志 | 同上 | **勾选监听制**（见下）；含运行时引脚值 |
| 4 | 致命错误 | 关卡目录 `external_lua_file\ErrorLog.txt` | 循环调用/挂载失败类；无文件 = 未发生 |
| 5 | 编辑器存档面 | `Beyond_Local_Save_Level\<地图ID>\` | 主件滞后，**Temp 才新鲜，双查** |
| 6 | 编辑器日志 | 游戏安装目录 `BeyondAssets\BeyondAssistEditor\Log\log.txt` | 会话连接与状态机观察窗；logPre.txt = 上一会话 |

## 三、两条关键机制（误判高发区）[J，2026-09-30]

1. **.gia 日志的写入者是编辑器**：链路 = 运行时 → 传输 → 编辑器收集器 → 落盘。
   推论：**游戏内直接试玩 = 零 .gia**（收集器不在场）
2. **节点图日志勾选监听制**：编辑器"窗口→日志→节点图筛选"须勾选目标图（服务器图
   上限 10 / 客户端 99）其执行才写日志；未勾 = 零文件，**与脚本是否执行无关**；
   **勾选状态每次会话重置**，每轮重新勾选

## 四、采集协议（标准操作）

```
试玩前：记录基线（各观察面当前状态：文件清单/最后修改时间）
（用户试玩）
试玩后：差分对比——
  · 新 .gia 文件 → 图执行条目 + Lua 输出
  · output_log 增量 → isTrial 开跑信号 ± 窗口内的事件（判定执行位置：
    云端场景 or 本地执行）
  · 新 .gir 文件 → 局内运行时数据
```

读取顺序：差分总览 → 要 Lua 细节 → 解最新 .gia（可读字符串抽取）→ 要平台行为 →
output_log 搜关键词。

## 五、测试纪律（一次试玩榨干）

1. **单变量原则**：一次试玩只验一批预写判据——拒绝"试一下看看"
2. **预写判据**：试玩前明确"看到 X = 判 Y"
3. **失败冻结**：连续两轮无进展强制停下，先穷尽本地可读源（参考样本/API 文档）
4. 试玩是昂贵的人力操作——只做判决，不做理论筛选

## 六、运行时证据能读到什么（历史验证样例）

| 观测 | 通道 | 验证过什么 |
|---|---|---|
| 打印字符串原样回读 | .gia 执行条目 | 执行边通路 |
| 变量名 + 运行时值 | 执行明细 | 变量寻址/黑板读写 |
| 信号回执逐字 | .gia + output_log | 信号链与 OnInit 注册时序 |
| 循环迭代数 × 轮次 | 执行明细 | 控制流含端语义（1..N 含两端） |

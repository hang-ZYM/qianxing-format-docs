# 参考 · 未完成项台账

> **读者为什么需要知道这个** —— 这份文档不解决任何问题。它做的是另一件事：把散在各篇「未确定项」小节、各册「未定 / 待核」清单里的东西收拢成一份可查的总账，让「我们不知道什么」变成一张能逐条追源的清单。不读它，你会把正文里一条条「推断」当成已经落地的结论。

**前置**：建议先读 [00 设计说明](00_设计说明.md)——它的**原则 4「诚实」**讲的就是这份台账的由来。术语沿用 [参考_术语表](参考_术语表.md)。

---

## 一、这份台账是干什么的

**它不解决任何问题。** 它只做一件事：把「未知」从一种印象变成一份清单。

本仓有一条纪律：未完成项、失败路径、试过但没成的路，照写；没验证的东西不混进正文当结论（[00 设计说明](00_设计说明.md) 原则 4、[12 纪律](12_纪律.md) 第五节）。各篇于是各自留了一节「未确定项」。散着看，它们是各篇的尾巴；聚起来看，它们才是这个项目**当下真实的边界**——哪些结论只到「推断」、哪些字段还缺一次取证、哪些机制还没实测。

**「未知」不是结论，是「还缺一次取证」。** 这一条要单独说，因为它最容易被误读成「这条路堵死了」。本仓真实发生过：早先「单位状态组件落在哪个组件 id」这一格标的是未知；后来用户在编辑器里挂了一次状态，**一次真实样本就把这一格定了案**（见 [04 对齐](04_对齐.md) 第四节）。所以台账里每一条「未知 / 未定」，指的都是一个**状态**，不是一个**判断**——它会变，而且指得出它需要什么才能变。

### 记一条的规矩

- **每条必须能追到出处**：某篇的「未确定项」小节，或某份清单（`手册/20` §13、`手册/31` §11、内部审计报告的「不得以确定语气写入」栏）。查不到出处的不进表——不编。
- **「卡在哪」要具体**：缺一个真实样本？缺一次单变量实验？缺实机验证？缺一个编辑器操作？缺一次实现？写笼统了，这条台账就没用。
- **它是活的**：一条取证走完，它就该从这张表上划掉、升进正文并标出新的证据等级（升格路径见 [04 对齐](04_对齐.md) 第三节四步法）。同一张表，也是记录「哪些推断被否」的地方（[12 纪律](12_纪律.md) 第四节）。

## 二、分组

按「卡在哪」的性质分六组。组名本身就是这一条当下最缺的东西。

| 组 | 性质 | 卡在哪 |
|---|---|---|
| **A** | 等待实机验证 | 缺一次导入 / 试玩 / 人眼确认（对照件多已备好） |
| **B** | 等待单变量样本 | 缺一次「只改一个变量、对比差异」的对照实验 |
| **C** | 等待真实样本 | 缺一张原生样本本身（含「抽不到」：全档零使用，反推不出来） |
| **D** | 纯未知 / 未定案 | 还不知它是什么，或眼下没有可做取证的入口 |
| **E** | 口径与定义未定 | 事实可能有，但术语 / 判定标准 / 流程尚未成文 |
| **F** | 工程实现待补 | 不缺取证，缺一次实现（模块、引擎、检测） |

## 九、怎么用这份台账

- **找一条结论可不可信**：先在正文里看它的证据等级，再到本表查它有没有一条「同一件事」的未完成项——有，说明它还没升格到位。
- **想推进一条**：看它「需要什么才能推进」那一列，那就是它缺的那一次取证。取证走完，改的是正文与本表两处：正文升等级（[04 对齐](04_对齐.md) 第三节第 4 步），本表划掉该行。
- **新挖出一条「未知」**：先落进对应篇目的「未确定项」，再同步进本表——不要只留在会话里。

一句话：**这份台账不产出结论，它只让「我们还缺哪几次取证」变得可查、可数、可逐条销账。**

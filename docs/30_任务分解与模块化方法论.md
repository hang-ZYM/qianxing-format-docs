# 30 · 任务分解与模块化方法论（封闭格式平台的 AI 内容生成）

> 本卷面向想在**闭源二进制格式**的 UGC 游戏（或任何"平台是唯一裁判、错误无报错"的封闭
> 系统）里做"AI 辅助内容生成"的读者。它回答一个问题：为什么"一句话生成一张关卡"必然
> 失败，以及用什么工作方式替代。方法从本项目的工程实践中泛化而来，不含任何平台特定
> 实现；平台事实的例子引用公开卷（[22](22_最小图正典与模板.md) / [23](23_运行语义实证.md)），
> 验证方法论总纲见 [06](06_验证方法论.md) 与 [28](28_验证方法与发现.md)。

## 1. 问题：端到端生成为什么必然失败

设生成一张可玩关卡要经过 n 个环节（合成容器、构造节点、装配引用、通过装载、运行正确……），
每个环节的独立合格率为 p：

- 端到端一次生成的合格率 = p^n——p=0.9、n=10 时只剩 35%，且 n 随作品复杂度只增不减；
- 封闭格式的独特恶化因素是**静默降级**：平台对坏内容的表达不是报错，是"东西不见了"
  （docs/02 定律 1）。错误不在发生点暴露，而是传播到链条末端，以"整体不对"的形式出现；
- 于是端到端失败后**无法归因**：十处嫌疑、零条线索，修复循环不收敛。实践中表现为 AI
  反复重新生成整个产物，每次修好一处、换坏另一处。

结论不是"生成能力不行"，是**结构不行**：验收点只有一个（终点），而复杂度要求验收点
分布到每一环。方法由此确定——任务分解 + 逐步验收。

## 2. 方法：分解、逐步验收、日志为权威状态

三步循环：

```
分解  意图 → 子任务序列             （编排者的工作）
执行  每个子任务 = 调用一个已验证操作 （操作库的工作，§3）
沉淀  反复出现的子任务 → 固化为新操作入库（库随创作成长，§6）
```

核心数据结构决定：**已验证操作日志是权威状态，产物只是日志的投影。**

- 每条日志记录：操作名、参数、验收结论、产物版本号——凭它可以从任意空状态重放出
  产物，也能事后审计"这个字节是谁写的"；
- 为什么产物不配当权威：产物会被平台改写（导入器重编号标识符是常态，docs/29 §2）、
  会损坏、会丢失；日志不会。产物对不对，永远问日志；
- "产物任意时刻都有效"由此从**纪律**变成**数据结构性质**：验收不过的调用不写日志、
  不产生新版本（§3 回滚），于是"日志的最后一版 = 最后一个已知好状态"成为恒等式，
  不需要任何人自觉维护。

| 内建性质 | 由哪条机制保证 |
|---|---|
| 产物恒有效 | 后验不过 → 拒绝 + 自动回滚；坏调用不产生新版本 |
| 失败只损失一步 | 版本制：每次通过落一版，回滚 = 版本指针回拨 |
| AI 复杂度有界 | 编排者一次只生成一批操作；每个操作语义单一 |
| 能力沉淀 | 新子任务 → 入库 → 下次直接调用（§6） |

## 3. 两级任务粒度

**功能级**（编排单位）：一个用户可感知的子目标——"合成一张图 / 装配进关卡 / 交付验收"。
编排者（AI）在这一级工作：拆意图、排顺序、读结果、定下一步。

**操作级**（原子操作）：功能级由操作级组成，每个操作是一份四要素契约：

| 要素 | 内容 | 失败语义 |
|---|---|---|
| 前置检查 | 状态不满足即拒绝（依赖就绪、目标未占用、版本可写） | **不计失败**——是"此路不通"，换路 |
| 执行 | 确定性代码，同输入必同输出；**不在此环节调用 AI** | 失败计一次（§7 轮换律） |
| 后验 | 该操作可达的最高级验收（§4） | 不过 → 自动回滚 + 计失败 |
| 回滚 | 恢复到调用前版本 | 保证失败只损失一步 |

两条边界纪律：

- **副作用领地制**：一个操作只允许写三处——当前产物的新版本、自己的资产库、日志。
  不碰其他操作的领地；
- **编排者只组合、不实现**：编排者不得现场发明操作；库外需求 = 先按 §6 把它造成操作
  再调用。能力沉淀在库里，而不是散落在某次会话里。

## 4. 验收分级：后验取可达最高级

| 级 | 名称 | 判什么 | 本仓库对应 |
|---|---|---|---|
| L1 | 字节级 | 写出的字节可被自己的解析器往返复现（encode(parse(x))==x） | `qxfmt roundtrip` |
| L2 | 结构级 | 满足已积累的实证格式规则 | `qxfmt verify` |
| L3 | 装载级 | 平台装载接受，内容逐节点存活（节点级对照，docs/06 §10） | 导入观察 + 重保存对比 |
| L4 | 运行级 | 执行语义符合预期（执行记录逐条回读） | docs/23 的观察面 |
| L5 | 人审 | 视觉/体验验收 | 用户 |

原则：

1. **每个操作的后验取它可达的最高级**——能判 L2 的操作不要停在 L1。分级不是形式，
   每一级都要有机器可读的判据与判定记录；
2. **判级要诚实**：L2 全绿 ≠ L3 会过。本项目实测四类异常离线校验全 PASS、装载后内容
   仍被剥（docs/28 §1.2）——"知道自己不能判什么"与能判什么同等重要；
3. 若平台提供快速判定通道（本项目图域有概念级描述，docs/28 §三），把它作为该域操作的
   首选后验——验收回路越短，修复循环收敛越快；
4. L5 不可外包给机器：机器产出判据与证据（预写"看到 X = 判 Y"），人只做终审。

## 5. 仲裁规则：金样本字节 > 文档断言 > 枚举名

三条证据来源冲突时按此序仲裁：

| 来源 | 是什么 | 为什么排这个位置 |
|---|---|---|
| 金样本字节 | 平台原生创建/接受的产物的实际字节 | 平台自己的输出，最高权威 |
| 文档断言 | 逆向笔记、schema 注释、手册记载 | 可能过时，可能本来就是错的 |
| 枚举名 | 从名字/编号归纳的对应关系 | 最弱——名字是研究者贴的标签，会继承被检验的假设 |

**真实翻案案例**（本项目 2026-10 的审计记录）：

- 立法：某资产库条目的配置段存在"段号 k → 载荷字段 k+10"的偏移律，两个域共 14/14
  样本吻合，立为定律写进卡片；
- 翻案：按金样本做全档扫描，反例遍地——42→f55、70→f75、21→f30、6→f21、73→f78、
  8→f16（职业条目自己就是 +8）；另一批 39→f49、35→f45、1→f11 恰好吻合；
- 复核结论比翻案本身更疼：所谓"14/14"的验证过程有缺陷——职业条目自身 10 段中至少
  4 段不符，当时**不可能**全验过。定律是在没数清样本的情况下立的；
- 双源定案：反编译读出的字段写盘序号（机器事实）+ 资源树条目与资产库条目按 guid
  三向对账，独立证实偏移并无规律。

三条教训（与 [docs/06](06_验证方法论.md) 元律 M2/M3 同源）：

1. **吻合不是验证**：14 个样本吻合只说明"没找到反例"，不说明"定律成立"；
2. **同源证据不叠加**：14 个样本若来自同一种归纳方式，证据力等于 1 个样本；
3. **金样本一票否决**：字节反例存在即翻案，无论文档写得多自信。

## 6. 操作库的成长制度

操作库是这个方法论的资产。成长制度四条：

1. **入库五条标准**（缺一不入）：

| # | 标准 | 内容 |
|---|---|---|
| 1 | 审计先行 | 实现前先对正典（平台原生金样本）出差异清单——先弄清要仿什么 |
| 2 | 实现 | 确定性代码 + 四要素契约完整（§3） |
| 3 | 金样自证 | 好件全过 + 病件全拦（对抗测试集，docs/06 §9） |
| 4 | 诚实状态位 | PASS / 待验证 / 未实现——禁止过度声明完成度 |
| 5 | 遗留清单 | 已知边界与未决问题随操作卡入档 |

2. **≥2 次复现才固化**：创作中反复出现的子任务才值得做成操作；一次性意图不强行
   模块化（过早抽象的维护成本高于重复劳动）；
3. **一操作一卡**：接口、契约、测试判据、遗留问题，入库时建卡——卡片是操作库的
   文档形态；
4. **只许调用库内操作**（§3 边界纪律的重申）：这是制度的关键一条——没有它，能力会
   以"这次先手动搞一下"的形式流失掉。

## 7. 失败处理：轮换律与履历回流

- **单操作 ≤4 轮**：同一操作连续 4 次被后验拒绝，判"此路不通"而不是"再试一次"——
  第 5 次重试的期望收益趋零，机会成本是整条产线停摆。4 是经验值，关键是**重试上限
  必须存在**；
- **前置失败不计失败**：前置不过 = 换路（条件不满足不是错误）；后验失败才计失败；
- **失败履历回流分解**：运行级判败不回滚产物（产物仍有效），而是把判决与观察数据
  （执行记录、存活对照）回流给编排者，分解出修复调用序列。失败是信息，不是终点。

三种失败、三种损失（由 §3 机制自动保证，不靠自觉）：

| 失败点 | 发生什么 | 损失 |
|---|---|---|
| 前置拒绝 | 不执行，换路 | 零 |
| 后验拒绝 | 自动回滚 + 计失败 | 一步 |
| 运行级判败 | 不回滚；判决回流 → 修复序列 | 触发修复（产物仍有效） |

## 8. 与本仓库的关系

本仓库是这个方法论的静态投影：

| 方法论构件 | 本仓库实现 |
|---|---|
| L1 字节级验收 | `qxfmt roundtrip`（容器与树往返验证，[QUICKSTART](../QUICKSTART.md)） |
| L2 结构级验收 | `qxfmt verify`（实证规则离线校验，compose 时自动执行） |
| 验收边界测绘 | [docs/28](28_验证方法与发现.md) §1.2（离线判不了什么，与能判什么同等重要） |
| L4 运行语义基准 | [docs/23](23_运行语义实证.md)（"写对了"在运行时的含义） |
| 金样本与模板 | [docs/22](22_最小图正典与模板.md)（编辑器原生最小图 = 正典起点）+ `templates/` |
| 操作单元的公开文档形态 | [manuals/](../manuals/00_目录与使用说明.md)（22 册任务导向操作手册，按任务查册） |

给想复制这套方法的读者一句话：**先建验收，再建生产**。规则从平台行为回填离线校验
（docs/28 §一），让每一类犯过的错误此后都能在本地拦截——这是整个体系里唯一只会
单调增长的资产。

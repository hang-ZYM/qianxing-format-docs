# 22 · 最小图正典与模板（一个合法最小图长什么样）

> 证据：[A][J]。这一篇解剖**编辑器自己新建图时生成的默认模板**——它是"编辑器认可的最小合法图"的金标准（原生创建，符合 docs/06 §2 金样本纯净性）。想从零生成图的工具，应以它为正典起点。
> 模板实测体积约 190 字节——"一张能跑的图"比想象中小得多。

## 1. 默认新图模板解剖 [A]

编辑器新建一张节点图时，默认内容是**两个节点 + 一条执行边**：

```
[事件] 实体创建时 (kernel_ref → 词表id 71) ──执行边──→ [动作] 打印 (kernel_ref → 词表id 1)
                                                            └─ 文本参数: "测试"（TEXT_INPUT 控件）
```

要点：

- **起点是事件节点**——图必须有执行入口才可能有行为（docs/16 §4、docs/23 §2）；
- **终点是动作节点**——默认模板就是"事件→查→判→做"四段式的最小实例（省略中间两段）；
- 打印节点的文本参数是完整的 TypedValue（控件类型 + is_value_set + 包裹的 String 值，docs/03 §2.4）——**最小图的值也要走完整形态**，没有"裸字符串"捷径；
- 两个节点各带画布坐标（网格单位，docs/03 §2.2）——坐标不影响执行，但影响编辑器里的呈现位置。

## 2. 图的最小完备构成

从模板反推，一张被编辑器接受的图至少需要四类元素（字段语义见 docs/03 §2）：

| 元素 | 必备内容 | 说明 |
|---|---|---|
| 图身份 | ResourceLocator，f5 = 图 guid | guid 必须未占用（见 §6） |
| 节点 ×N | f1 index（稠密）、f2 shell_ref、f3 kernel_ref、f4 引脚 | kernel_ref 指向词表 id；泛型节点须已决议（docs/04 五件套） |
| 引脚 | f1 shell_sig / f2 kernel_sig（0 基，=0 省略） | 有值的引脚再带 f3 TypedValue |
| 边 | 存于**源引脚** f5 | 结构见 §3 |

黑板变量池（f6）可以为空——最小图不需要变量。

## 3. 边编码 [A]

连线不存独立列表，**存在源引脚的 f5 字段里**（repeated NodeConnection，docs/03 §2.3/§2.5）。默认模板的执行边实例：

```
源引脚.f5 = [ {
  f1: 目标节点 index,
  f2: { f1: 1 },        # 对端 shell_sig：kind=1 (IN_FLOW)，index=0 省略
  f3: { f1: 1 }         # 对端 kernel_sig：kind=1 (IN_FLOW)，index=0 省略
} ]
```

两种边的对端 kind 语义 [A]：

| 边类型 | 存储位置（源侧） | 对端 sig 的 kind |
|---|---|---|
| 执行边 | OUT_FLOW 引脚的 f5 | 1（IN_FLOW）——shell 与 kernel 都是 1 |
| 数据边 | OUT_PARAM 引脚的 f5 | 4（IN_PARAM）——shell 与 kernel 都是 4 |

注意：

- 记录的 sig 是**对端（目标）引脚**的签名，不是源引脚自己的；
- 类型错配的数据边在加载时被静默丢弃（docs/02 定律 5）——边的两端类型必须严格一致（docs/14）。

> **与 docs/03 的对账**：03 §2.3（引脚 f5 = repeated NodeConnection）与 §2.5（NodeConnection 结构）是同一事实的字段级记载；本篇补上的是**对端 sig 的 kind 语义**（执行边 1、数据边 4）与省略规则（index=0 省略）的实例化说明。

## 4. 字节手术方法论

在模板上做修改的标准流程（"模板手术法"）：

```
全递归解析（parse） → 定点修改（串/名字/guid） → 重编码（encode） → 往返验证
```

**往返验证铁律**：`encode(parse(x)) == x` 必须先于任何修改成立——往返不一致说明你的解析器对该文件有理解偏差，此时改出来的东西必然坏。

为什么必须全递归而不是局部替换：

- 嵌套的**长度前缀是雷区**——改一个串的长度会级联影响所有外层容器的长度字节，手补必漏；
- protobuf 高字段号 tag 的 varint 编码、包裹消息形态等约束（docs/03 §4 编码速查）在重编码器里自动满足，手工逐字节替换则每一条都是隐患。

## 5. 从模板到任意图

模板手术能覆盖的增长轴：

- **换文本**：改打印参数 / 各节点的 TypedValue；
- **换事件/动作**：换 kernel_ref 指向的词表 id（引脚签名同步按词表重建）；
- **加节点**：递增节点 index（保持稠密），复制同类节点的引脚结构；
- **加边**：按 §3 的编码在源引脚 f5 追加 NodeConnection；
- **加变量**：f6 追加 GraphVariable（运行态语义见 docs/23 §5）。

复杂形态（数据流、多参数、分支）的边模式，从**真实语料图**（编辑器原生创建的样本）提取同类节点的连线字节作为模板——不要凭签名表想象（docs/06 §2）。

## 6. guid 分配注意事项 [J]

- 图 guid 在用户空间内必须唯一——**分配前全档扫描**既有占用（guid 段位表见 docs/10）；
- 实证教训：撞号会出现"内容被顶掉/名字错乱"等无提示的诡异行为（静默降级，docs/02 定律 1）；
- 实用策略：选当前存档未使用的**空段**号码，避开历史上用过的区间。

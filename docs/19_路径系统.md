# 19 · 路径系统（f32）

> 官方文档 × 字节解码（1975 图真实样本）。

## 1. 官方语义

路径 = 一组有序的**路点**（只有位置和旋转），用于：
- **造物巡逻**（未入战-巡逻功能）
- **基础运动器的关卡路径运动**（沿路径移动的平台/机关）

巡逻循环类型：单程 / 往返 / 循环。

## 2. 字节结构（已解码 ✅）

```
f32 (路径库)
 └─ f1 (路径对象) × N
     ├─ f1: guid (0x400段, 如 0x40000004)
     ├─ f4: 命名组件 {f1:1, f11:{f1:"路径名"}}     ← "路径"/"圆圈"/"测试"...
     ├─ f4: 路点列表 {f1:54, f64:{f1:{...}}}        ← 组件ID=54, 配置字段=64
     │   └─ f1 内: repeated 路点
     │       ├─ f1: 实体索引 (int, 指向f5实体列表的序号)
     │       └─ f501: 路点顺序号 (0, 1, 2, ...)
     └─ f5: 变换 {f1:1, f11:{缩放1/1/1, f501:-1}}   ← 默认变换
```

## 3. 路点 = 引用实体

**关键发现**：路径的路点不是内嵌坐标，而是**引用场景中的实体**：

| 路点 f1 值 | 对应实体 | 含义 |
|---|---|---|
| 2 | 实体[2] guid=0x41000001 | 出生点实体 |
| 4 | 实体[4] guid=0x40c00003 | 路点标记实体 |
| 3 | 实体[3] guid=0x40c00002 | 路点标记实体 |
| ... | ... | ... |

被引用的 **0x40c 段实体**（aid=1000000）就是**路点标记**——编辑器在场景里放置的不可见标记实体。路点的实际世界位置存在这些实体的位置组件（f6#1/f11）里。

**设计意图**：路点是真实实体 → 移动路点标记的位置就更新了路径 → 引用该路径的巡逻/运动自动跟随。这是**引用而非拷贝**，和 prefab 实例化同一哲学。

## 4. 真实样本（1975 图 5 条路径）

| 路径名 | guid | 路点数 | 路点实体索引 |
|---|---|---|---|
| 路径 | 0x40000001 | 1 | [2] |
| 圆圈 | 0x40000003 | 1 | [2] |
| 测试 | 0x40000004 | 7 | [2,4,3,5,6,7,8] |
| 测试_1 | 0x40000005 | 7 | [2,4,3,5,6,7,8] |
| 测试_2 | 0x40000006 | 7 | [2,4,3,5,6,7,8] |

"测试"系列复用同一组路点（不同顺序号的同批实体引用）——**路径可以共享路点**。

## 5. 组件定律再次验证

路径对象用 `{f1: 组件ID, f(组件ID+10): 载荷}` 组织：
- 组件 1（f11）= 命名
- 组件 54（f64）= 路点列表

**这验证了组件定律（f = ID+10）在路径对象上同样成立**——路径、实体、模板库全部统一用同一套组件系统。

## 6. 与巡逻系统的关系

路径被造物的**巡逻模板**引用（官方文档）：
- 巡逻模板配置：路径 + 循环类型（单程/往返/循环）+ 巡逻起始位置
- 造物在未入战状态沿路径移动
- 节点图 Trigger：`177 路径到达路点时`（到达某个路点触发事件）

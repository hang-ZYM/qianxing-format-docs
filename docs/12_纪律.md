# 纪律：在一个只能试出来的系统里，凭什么说"这是对的"

> **读者为什么需要知道这个** —— 这套纪律不是因为道德要求才守的。千星奇域是一个封闭系统：没有 SDK、没有公开文档、没有源码，里面的一切只能"试出来"（[03 两岸一桥](03_两岸一桥.md)）。在一个只能试出来的系统里，不守这套纪律就没有可信结论可言——你会把类推当事实、把巧合当规律、把"对上了"当"能用"。本篇把散在各处的规矩收拢成一个总纲，每条说清三件事：**它管什么、不守会怎样、在哪儿能看到它落实**。

**前置**：[00 设计说明](00_设计说明.md)（四条写作原则，本篇是它的展开）、[03 两岸一桥](03_两岸一桥.md)（两侧性质）、[04 对齐](04_对齐.md)。

**本篇的分工。** 本篇是**纪律总纲**：每条纪律只讲**为什么要有它、它管什么、不守会怎样**。**具体做法**（怎么验、有哪些检查项、判例、以及七条**元律**本身）在参考层 `手册/06_验证方法论.md`——按"查手册"的路径进去，那里给的是可操作的清单；**仲裁规则原表**在 `手册/30` §5；**四步法**（一条映射怎么加进去）与真实例子在 [04](04_对齐.md) 第三节；**证据等级四档**（字节实证 / 官方文档 / 人工核验 / 推断）在 [00](00_设计说明.md) 原则 3。以上各部分本篇只引用、不重抄。

## 一、证据优先级：字节 > 文档断言 > 枚举名

### 它管什么

同一个事实，手上可能同时有几种来源；它们说不到一块去时，谁说了算。本仓库的排序是：

> **真实样本的字节 > 文档里的断言 > 枚举名 / 类名。**

这是一条**仲裁规则**，只在冲突时才动用到它。三种来源一致时没人会想起它；它存在的意义，是它们打架的那一天。

### 为什么是这个顺序

- **字节在最下游。** 它不解释自己，但它是系统实际吃进去、吐出来的东西。文档可能写错，字节不会替文档圆场。
- **文档断言可能只是类推。** 真实例子：`手册/01` 曾把 `.gis` 的容器类型码记成 `2`，实测是 `6`（同期复核 `.gil` = `2` 不变）。那个 `2` 很可能是**从 `.gil` 类推来的**——一个类推值被写成了断言。这正是"证据分级"要挡的那类错误：**类推不标注，就会被读成事实**。
- **枚举名离事实最远。** 名字可能是研究者贴的标签，也可能是从混淆代码里抠出来的残留；编辑器二进制里的混淆名**随版本重生成**（[03](03_两岸一桥.md) 第二节），同一个编号在不同版本可能挂着不同的名字。名字还会继承被检验的假设——`手册/30` §5 把枚举名的证据力定为"最弱"；类型码的官方枚举名至今未定位，赋值点就在混淆代码内（`手册/18`）。

### 一条铁律

**枚举名 / 类名不能单独作为结论，只能作为线索。** 它的正确用法是"往这边查一下"，不是"所以它就是这个"。挖字段时靠一个名字找到地方，可以；拿一个名字当定论，不行——那正是上一条 `.gis` 类型码走过的路。

### 在哪能看到它落实

[00](00_设计说明.md) 原则 3 的四档等级；[04](04_对齐.md) 对照表的「证据等级」列（每一行都必须落到某一档，不许空着）；`手册/30` §5 的仲裁规则原表。

## 二、双重来源验证

### 它管什么

**一个结论要有两个独立来源共同证实**，单源不立律。"独立"是关键词：两个来源得是**真的两回事**，不是一句话被抄了两遍。

### 为什么

单源有三种坏法：

1. **巧合。** 一次实验出了预期结果，可能是这个变量，也可能是当时环境里另外某个没留意的因素。
2. **版本差异。** 两个样本来自不同版本，它们之间的差异本来就不该拿来比对。
3. **同一个错误的两次传播。** 这是最阴的一种——两个来源看着独立，来历其实是同一条链。所以判定独立性，问的不是"几条"，是**"它们的来历是不是同一条链"**；同源证据不叠加（参考_术语表 §1.3：14 个样本若来自同一种归纳方式，证据力等于 1）。

### 真实例子（只讲方法）

- **远雾点距离**（[04](04_对齐.md) 2.C）：一处来历是作者预设里"望远"=3000、"挡视线"=200 的单调对应；另一处是用户实机把值设成 40 生效。前者是静态样本的规律，后者是动态实机行为——两条链不同，共同钉住同一个字段。
- **元件组成员旋转**（[04](04_对齐.md) 第三节第 2 步）：A、B 两包只差一处，一包转了、一包没转。两个可对照的结果互为印证，字段语义当场定案；这是"双源定案"在实验层的形态——结论由两个结果共同立起，不由一次观测立起。

两条都不涉及任何一关的成品内容：讲的是来源之间怎么互相独立，不是关卡里放了什么。

### 在哪能看到它落实

[04](04_对齐.md) 第五节要求每一行都能追到出处（"没有出处的一律标推断或未知"）；[07](07_任务分解.md) 的日志把每次调用的参数与验收都留档，是为了让两个来源**事后还能被重新核对**，而不是只在当时口头上成立。

## 三、单变量判定

### 它管什么

**一次只改一个东西，对比差异；一步一个变量，一步一次判定。** 拒绝"试一下看看"式的实验。多个可疑点怎么逐级定位（**逐级二分**）属做法，见 `手册/06` §3；本节只讲它为什么是唯一办法。

### 为什么它是唯一办法

在封闭系统里，字段的语义**读不出来**——没有类型声明、没有文档给它背书。想定出一个字段是干什么的，能靠的只有一件事：**改它，看什么变了**。只改一个，变了的就归给它；一次改好几个，就分不清是谁的功劳。这就是"[改真实样本 → 只改一处 → 看差异]"这条取证打法成立的全部理由。

### 和 07 的关系

它是同一个原则在两个层上的落点：

- 在**取证层**，它是定位字段语义的标准打法（[04](04_对齐.md) 第三节第 2 步）；
- 在**任务层**，它是"每步独立可验"（[07](07_任务分解.md) 第三节）——一个愿望在字节层可能是四个独立旋钮，"一次改四个、没生效"时你不知道是哪个错了。[07](07_任务分解.md) 把这句话写成了："一步一个变量，一步一次判定。"

同一件事：取证时要能归因到唯一一个变量，分解任务时要能归因到唯一一步。这不是两个习惯，是一个原则的两个落点。

### 与四步法的关系（引用，不重抄）

"一条映射怎么加进去"的四步法在 [04](04_对齐.md) 第三节：找真实样本 → 单变量判定 → 确认粒度 → 写入并标等级。本节讲的是其中第 2 步**为什么必须这样**；四步的完整流程与真实例子不在此重抄。这里只补第 3 步一句，因为它常被跳过：**"对上了"不等于"能用"**。字段对上了、结构门全 PASS，导入后仍可能卡死；那是粒度级的问题，字段级看不出来。"能用"是比"对上了"更高的一级判据，得单独走一次。

## 四、真实样本优先

### 它管什么

**结论只能从真实样本长出来。** 编辑器原生创建的产物是**权威基准**；没有样本就没有结论，**不许凭空推字节**。

### 为什么

反过来看更清楚：凭空推出来的字节，无法和任何东西对照，也就无法被证伪——它既不能算错，也不能算对，只能算"还没落地"。而真实样本提供可复核的锚：这个字段在这里是几，样本里读得出来；这条链能不能跑，样本跑得出来。所以 [04](04_对齐.md) 第三节第 1 步把话说死了：**没有样本就没有这一行**。

一条边界：用来归纳规则的样本，必须是平台**原生创建 / 接受**的产出；**不得**用"平台保存过的第三方内容"归纳规则——那是循环论证。定义见 参考_术语表 §1.3"真实样本"；判例与操作口径见 `手册/06` §2。

### 人眼只提供一次

有一类东西机器判不了，得靠人看一眼——比如模型长什么样、某个视觉效果对不对。这类**看不见的东西由人确认一次**，确认完就按等级（人工核验）**写进表**；此后**查表**，不再反复问同一个人。

这和第一条是一根线：人工核验一旦入表，就成了一条有出处的证据，可被引用、可被复核；反复口头确认则既没有留存，又会因为"问的都是同一个人"而**退化成单源**。

### 人的实测压过我们的推断

人的实测也是一种真实样本，而且它压过我们的推断。

真实例子：某个值的档位，我们推成一档，人实测选了另一档，**以人的为准，并记录我们的推断被否**。雾色即如此——雾色报告定案纯黑，凭的是用户实测优于我们先前设的冷蓝；这一格随之从"推断"升到"人工核验"（[04](04_对齐.md) 2.C）。

"记录推断被否"本身也是纪律：被否掉的推断不能悄悄删掉，要留着，说明这里曾经推错过、错在哪。

### 在哪能看到它落实

[06 模块化](06_模块化.md) 契约四要素的前置检查里就有"真实样本图不在位 → 换路（不计失败）"——没有样本，这一步根本不该开始；[06](06_模块化.md) 第四节"入库五条标准"第 ③ 条是**真实样本自证**：好件全过、缺陷样本全拦，才算自证。

## 五、诚实

### 它管什么

**怎么说。** 三条：未完成项、失败路径、试过没成的路，照写；推断必须标推断；"未知"不是结论。

### 未完成与失败，照写

一份说"我们不知道 X、试过 Y 失败了"的文档，比一份什么都敢说的文档可信得多（[00](00_设计说明.md) 原则 4）。失败路径尤其要写，因为它替后来的人省掉一条已经走过的死路。真实样本里也含"失败的样本"：路点锚索引重复导致运行时卡死那一次，字段级全对、结构门全 PASS，问题出在粒度级——它被记下来，是因为它是"对上了 ≠ 能用"的标本（[04](04_对齐.md) 第三节第 3 步）。

未完成项集中进各篇的「未确定项」小节，不混进正文当结论（[03](03_两岸一桥.md)、[04](04_对齐.md)、[06](06_模块化.md)、[07](07_任务分解.md) 都各有一节）。

### 推断必须标推断

**不许为了好看而抹平等级。** 一条映射今天只到"推断"，就如实写"推断"，等取证走完再升格（[04](04_对齐.md) 第三节第 4 步）。等级被抹平的后果不是"文档不好看"，是**读者没法判断该信到什么程度**——哪条能拿去改、哪条不能（[03](03_两岸一桥.md) 第二节）。

### "未知"不是结论，是"还缺一次取证"

这一条单列，因为它最容易被误读成"这条路堵死了"。

真实例子：早先的记录里，"单位状态组件落在哪个组件 id"这一格标的是**未知**；后来用户在编辑器里挂了一次状态，**一次真实样本就把这一格定了案**（`f7` 槽 `cid14` → 载荷 `f24`，[04](04_对齐.md) 第四节）。

所以"未知"标的是**状态**，不是判断：它代表"还缺一次取证"，**它会变**。另一种"未知"要分清——**"抽不到"**：全档零使用的字段，反推不出来，只能等一次原生样本（如物件 / 造物不可见的效果模板 id，官方有面板项但全档零状态使用）。一种是你还没试，一种是眼下没有样本可试；两者都写成"未知"，处置却不同。

### 在哪能看到它落实

[06](06_模块化.md) 入库五条标准第 ④ 条：**诚实状态位**（✅ / 🔶 / ⏳），禁止过度声明完成度；[07](07_任务分解.md) 第三节「可达性」：后验取该操作可达的最高级，判不了的级如实标 `PENDING-ANCHOR` / `PENDING-S1`，不美化；[00](00_设计说明.md) 第六节与 `mods/MODULES.md`「未开源边界」把"这里不讲什么"也写出来，读者才知道该信到什么程度。

## 六、引用要指向稳定的锚

### 它管什么

**怎么引。** 引用别处的内容时，指向**不会因为别处改动而失效的东西**——标题、节名、符号名。**不要指向行号。**

### 为什么

**行号引用一改就断，而且断得无声无息。**

真实例子（同一天里发生两次）：一次是重写 `QUICKSTART.md` 之后，`参考_术语表` 里引它的行号全部失效；一次是 `手册/30` 撤掉几节正文之后，术语表里引它的 9 处行号落空。**两次都没有报错、没有提示**——引用照旧"看起来是对的"，只是已经指向了别处，或者指向了空。

根子上：**行号是"位置"，不是"身份"。** 任何在前面插入或删掉内容的人，都会在你不知道的情况下把它挪走。

### 怎么做

- 引用写成**节名 / 标题 / 符号名**。例：不写 `手册/30:73`，写 `手册/30` §5 仲裁规则；不写 `mods/core.py:186-217`，写 `mods/core.py` 的 `run_module`。
- 同一条纪律的另一面：**被引用的一方改动时，有责任检查谁引用了自己。** 本次撤节那一步正是漏了这一检查，才留下 9 处空引用。

### 在哪能看到它落实

`docs/参考_术语表.md` 的引用已全部改为节名 / 符号引用（原有 174 处行号引用已清）；`手册/30` 在撤节后仍保持原节号不动，就是为了不打乱别处的按节引用。

## 七、声明范围：说清"我扫了什么"

### 它管什么

**怎么报。** 报告一件事做完了，要**同时说清它覆盖的范围**；范围之外的部分，明确标"未覆盖"。

### 为什么

**把"我做的范围"说成"全部"，和把推测写成事实，是同一种错。**

真实例子（同一次修复里）：上一轮的死链扫描，报告写的是"**全仓链接扫毕……无其它死链**"，而实际只扫了 `README.md` 与 `docs/` 两个位置。下一轮真做了全量扫描，结果是 **258 处**死引用、散在 **60 个文件**里——**比原报告说的 8 处多了三十倍**。

**错不在"扫漏了"**——漏是常态，谁都会漏。**错在"扫了两个地方，却说成全仓"。** 前者只是没做完；后者会让下一个人**不再去查**。

### 怎么做

- 报告结论时，**同时声明范围**：扫了哪些目录、用什么判据、**哪些地方没扫**。
- 范围不全就写"已扫 X、Y；**Z 未扫**"——**未扫的部分不是缺陷，是信息**。
- 与"诚实"那一条的分工：**诚实管结论怎么表述，这一条管结论的覆盖面怎么表述。** 一条可以表述得完全诚实、却仍然让人误以为它查遍了。

### 在哪能看到它落实

本轮全仓引用扫描的报告逐目录列出了覆盖范围（根 / `docs` / `手册` / `guide` / `mods` / `manuals` / `templates` / `examples` / `src` / `tools` / `tests`，共 115 个文本文件）；`docs/参考_未完成项.md` 的每一条都带"卡在哪"与出处。

## 结尾 · 这些纪律在哪落实

纪律不是写在纸上的态度，它在仓库里有对应的机制。下表是每条纪律的落点：

| 纪律 | 它管什么 | 不守会怎样 | 落实在哪 |
|---|---|---|---|
| **证据优先级** | 来源冲突时谁说了算 | 类推值被读成断言（`.gis` 类型码那条） | [00](00_设计说明.md) 原则 3 四档等级；[04](04_对齐.md) 对照表「证据等级」列 |
| **双重来源验证** | 一个结论要几个来源 | 巧合、版本差异、同源传播被当成规律 | [04](04_对齐.md) 第三节第 2 步；每行「备注」的出处链 |
| **单变量判定** | 一次实验改几个变量 | 多变量同改，错在哪一步不知道 | [04](04_对齐.md) 第三节四步法；[07](07_任务分解.md) 第三节"一步一个变量，一步一次判定" |
| **真实样本优先** | 结论从哪儿来 | 凭空推字节，无样本无结论 | [06](06_模块化.md) 契约四要素（前置：无样本 → 换路）；入库五条标准 ③ 真实样本自证 |
| **诚实** | 结论怎么表述 | 抹平等级、藏起失败，读者无法判断可信度 | [06](06_模块化.md) 入库五条标准 ④ 诚实状态位；[07](07_任务分解.md) 第三节可达性；各篇「未确定项」 |
| **引用指向稳定的锚** | 怎么引别处的内容 | 行号引用一改就断，而且断得无声无息 | [参考_术语表](参考_术语表.md) 的引用已全改为节名 / 符号名 |
| **声明范围** | 结论的覆盖面怎么表述 | 把"我扫的范围"说成"全部"，下一个人就不再查 | 本轮全仓引用扫描报告的逐目录覆盖声明；[参考_未完成项](参考_未完成项.md) |

前五条串起来是同一件事的五个面：**结论要有来源（证据优先级），来源要互相独立（双重来源），来源要能被一次一个变量地核出来（单变量判定），来源本身得是真实样本（真实样本优先）——而这一切，都要如实说出来（诚实）。**

后两条是它们的**交付纪律**：**结论要能被别人找到（引用指向稳定的锚），也要让别人知道它管多大范围（声明范围）。** 前五条决定"你说得对不对"，后两条决定"别人能不能接着用"。

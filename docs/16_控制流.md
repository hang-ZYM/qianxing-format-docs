## 2. 多分支的泛型机制

多分支(3)是泛型节点，只有 **T:Int** 和 **T:Str** 两个变体：
- `key`（控制表达式）= 要匹配的值
- `cases`（判断参数）= 要匹配的候选值列表
- 匹配到 Case N 就从 Case N 出口流出，都不匹配走 DefaultBranch

**推理**：这和编程语言的 `switch-case` 完全同构，且**只支持 Int 和 Str**（枚举值本质上也是 Int，所以覆盖了枚举匹配）。

## 3. 真实图的控制流模式

### 3.1 分支出口连什么（语料 Top）

| 双分支 True 出口连向 | 次数 | 含义 |
|---|---|---|
| → 双分支（嵌套） | **54** | 条件嵌套——多层判定链 |
| → 设置自定义变量 | 28 | 判定后写结果状态 |
| → 多分支 | 20 | 先判真假再细分场景 |
| → 设置图变量 | 12 | 同上但作用域在图内 |
| → 激活/关闭选项卡 | 11 | UI 联动 |

| 双分支 False 出口连向 | 次数 |
|---|---|
| → 设置自定义变量 | **30** |
| → 双分支（嵌套） | 10 |
| → 多分支 | 10 |
| → 设置图变量 | 8 |

**发现**：嵌套分支（分支→分支）**64 次**——这是控制流的主流用法。True 出口偏向继续深入判定（嵌套/多分支），False 出口偏向写默认状态（设变量）。

### 3.2 循环使用量

| 节点 | 实例数 |
|---|---|
| 列表迭代循环(509) | 13 |
| 有限循环(5) | 5 |
| 跳出循环(6) | 未统计（通常在循环体内） |

循环用得少（18 次 vs 分支 224+87 次 = 311 次）——**分支:循环 ≈ 17:1**。千星关卡逻辑以"条件判定"为主，迭代为辅。

### 3.3 执行链长度

从 Trigger 到最远执行节点的路径长度：

```
平均 5.4 步，中位数 6 步
最长 23 步（极端案例）
```

**含义**：大多数逻辑在 5-8 步内完成——Trigger → 取数据 → 判定 → 分支 → 动作，这是典型的"事件→查→判→做"四段式。

## 4. 执行模型总结

```
Trigger(事件源) ──→ Query(取数据) ──→ Arithmetic/比较(判定) ──→ Control(分支) ──→ Execution(做动作)
     57个              174个              101个                  3个                203个
   ─────────────────────────────────────────────────────────────────────────────────────────
     只有出流      无流(被引用即求值)    无流(同上)            入+出流            入+出流
```

**这就是千星节点图的完整执行语义**：
1. **事件驱动**：Trigger 被外界触发后点火（碰撞/定时器/变量变化/信号/实体创建...57种事件源）
2. **惰性求值**：Query/Arithmetic 不占执行位，被下游引用时才求值（Blueprint Pure Function 语义）
3. **顺序流转**：执行线定义"做完这个做那个"，一个 FlowOut 可连多个 FlowIn（广播，但实际罕见 2%）
4. **条件路由**：分支节点按布尔/值路由执行流到不同出口
5. **迭代**：循环节点用 Iteration 出口反复执行循环体，End 出口继续后续逻辑
6. **状态落地**：最终的 Execution 节点修改变量/控制实体/播放音效/切换界面——把结果**写回世界**

## 5. 控制流范式预言（v1.3 运行时终验更新）

- goto 不存在（节点图无法实现非结构化跳转）✅ 结构化编程
- while 循环不存在（只有 for，且循环次数上限受 start/end_index 限制）✅ **已运行时实证**：迭代数精确等于参数、防死循环设计成立（docs/23 §3）
- 协程/await 不存在 ✅ **已运行时实证**：同步执行、同帧多事件顺次且时序固定（docs/23 §2）
- 递归不存在（子图不能调用自己）——结构级定论（词表无调用自图的机制）
- 一个图的执行是原子的（不会被另一个图的执行打断）← 单线程语义（与 docs/23 §2 确定性时序一致）

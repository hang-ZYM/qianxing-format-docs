# 对齐：游戏概念 ↔ 字节位置 ↔ 项目侧原语

> **读者为什么需要知道这个** —— 这是整份文档里最实用的一页。它把已知的对应关系集中成一张可以查、可以增补的表：你能照着把「我想要什么」翻译成「游戏里的什么」。不读它，前面几篇给的是地图与性质，你手里仍然没有那张能落地的对照表。

**前置**：建议先读 [03 两岸一桥](03_两岸一桥.md)（本篇是它的落地）。术语沿用 [参考_术语表](参考_术语表.md)。

---

## 一、这张表是什么

三列，不是两列。

| 列 | 记什么 |
|---|---|
| **游戏概念** | 游戏里那个东西叫什么（编辑器界面的名字、官方文档的名字、或者我们自己给它起的名字） |
| **字节位置** | 它在文件的哪里：哪个容器、哪个槽、哪个字段、什么值 |
| **项目侧原语** | 我们用哪个模块 / 哪次调用去操作它 |

**为什么必须三列。** 「知道字段」和「能用代码操作它」是两件事，中间隔着一层封装。任何一条映射都可能出现下面三种状态，而两列表格会把它们抹平成一种：

1. 字段知道了，也已经有模块能写它 —— 可以直接用；
2. 字段知道了，但还没有模块 —— 只能手写字节，或者整块搬运；
3. 字段还不知道 —— 连位置都没有，谈不到操作。

三列表格的好处是：**每一条你都能看出它卡在哪一格上**。这也正是 [03 两岸一桥](03_两岸一桥.md) 说的「桥为什么难」——右岸一个愿望，落到左岸往往是一整串字节操作，而这一串里只要有一环没有原语，整条链就还是断的。

**证据等级**一律用四档（同 [00 设计说明](00_设计说明.md) 原则 3）：**字节实证 / 官方文档 / 人工核验 / 推断**。凡标注「推断」的，都是**尚未验证**的；**尚未对上的，字节位置一列写「未知」**。不给表格好看而抹平等级。

**出处简写**（下面各表「备注」列用到）：光照人话表 = 光照/环境/光源人话字段表；光照反编译表 = 光照反编译字段表；雾报告 = 雾·视野压缩报告；雾色报告 = 雾色处方报告；时间报告 = 关卡时间配置报告；单位状态报告 = 单位状态域·隐身报告；路径报告 = 步 1 路径行走报告；元件之战 = 元件通道与性能之战收获。

## 三、一行是怎么加进去的

这张表不是抄来的，是**长出来的**。每一行的来历都走同一条四步，任何人可以照着往里加行。

**第 1 步 · 找真实样本。** 要么在编辑器里做一次（造一个「真实样本」，编辑器原生创建的产物是权威基准），要么从现成关卡里找一个已经带这个功能的样本。**不许凭空推断字节**——没有样本就没有这一行。

**第 2 步 · 单变量判定。** 只改一个东西，对比字节差异。这是定位字节语义的标准打法。真实例子（**元件组成员旋转**）：A、B 两包只差一处——把旋转写进成员摆放表的那包转了，只写成员体的那包没转。一个变量、两个结果，字段语义当场定案（元件之战）。这也是「双源定案」的用法：结论须由两个独立来源共同证实才算数。

**第 3 步 · 确认粒度（最容易漏的一步）。** **对上了，不等于能用。** 一串操作完整不完整，要另外确认。真实例子（**路径行走**）：字段对上了、结构门也全 PASS，但导入后**卡死**——根因是路点锚索引在单条路径内重复，运行时建字典撞了重复键。字段级没错，粒度级错了。所以「能用」是比「对上了」更高的一级判据，必须单独走一次（在编辑器里做一次、或看运行时行为）。

**第 4 步 · 写入并标等级。** 确认到哪一级，就标哪一级：从真实文件读出的是**字节实证**；官方语料/界面原文是**官方文档**；人在实机里亲眼确认是**人工核验**；只有推理、尚未验证的一律标**推断**。**不许为了表格好看而抹平**——一条映射今天只到「推断」，就如实写「推断」，等第 3 步走完再升格。

还有一个反向过程值得写明：**「问路」**。挖字段时常常先挖出一个位置，回头看右岸能不能用它（[03 两岸一桥](03_两岸一桥.md) 的两种走法之一）。上面表里带「（顺序推断）」的行就是这种——字段位置是**字节实证**，但「哪个子字段对应哪一项」还是**推断**，等一次单变量实验来升格。

## 四、还没对上的（诚实）

把当前仍未知的映射集中在这里，不混进正文当结论。

- **物件 / 造物不可见的效果模板 id**：官方有面板项，但全档零状态使用，抽不到（候选 id 仅推断，不作数）。这是「造物隐身」走效果池唯一缺的一块料。
- **节点 308 的行为与适用范围**：能作用于哪些实体类型、是否等价静态可见性组件，全部未验（首试件已出，待人工目视检查）。
- **雾的浓度与「天空受雾浓度」落在哪个字节**：候选若干，无单变量样本，未定案。
- **高度雾 6 项与距离雾 6 项到字节字段的逐项对号**：多数仍是推断。
- **f38–f57 族**（强度 / 模糊程度 / 滤镜 / 光晕 / 天际线 / 星 / 银河的逐项）：官方有标签池，无单变量样本把字段号一一钉死。
- **点光源 / 聚光灯 = `f51` / `f52` 谁是哪个**：文档与默认值两路指向一种，字节行为学不符，悬案。
- **运动器类型标签 5 / 6（定点 / 关卡路径本体）**：全档无样本。
- **静态实体 / 逻辑实体在字节层有没有标记**：官方说静态更轻，字节层查无标记可写。
- **「远景层」是否有独立开关 / 资产 / 字段**：UI 表、语料、反编译三路均查无，故判「若存在则属引擎内建、UGC 侧无接口」（判据件待用户人工目视检查）。

**「未知」是会变的。** 值得单独说明一点：早先的记录里，「单位状态组件落在哪个组件 id」这一格是**未知**；后来用户按操作单在编辑器里挂了一次状态，一次真实样本就把这一格定了案（`f7` 槽 `cid14` → 载荷 `f24`）。这正说明上表标「未知」不代表永远不知道——**它代表的是「还缺一次取证」**，而不是一个结论。同理，「未知」也可能是**「抽不到」**：全档零使用的字段，反推不出来，只能等一次原生样本。

## 五、怎么用它

**顺着查（落位）。** 你想做某个效果，先在「游戏概念」那一列找它。

- 找到了，往右读：**字节位置**告诉你落在哪，**项目侧原语**告诉你用什么调。原语那格写「待建」，说明还得先手写字节或整块搬运。
- 找不到，说明这是个空白。它可能是一次还没做过的取证，也可能是一次已经做过、但还没写进这张表的对号。**先补表，再动手**——否则你会重新推导一遍已经有结论的东西。
- 只找到一半（比如字段位置有了、原语没有），说明这一条卡在两格之间：这正是 [03 两岸一桥](03_两岸一桥.md) 说的「中间那段」。

**反着查（问路）。** 你挖出一个位置，想不出能用它干什么，就从「字节位置」往左回看「游戏概念」——很多设计决定是这么倒着长出来的。

**自己增补。** 按第三节的四步走，每一步都留下出处（哪个报告、哪次判定）。没有出处的一律标「推断」或「未知」，不要留一条来源不明的行在表里。

## 可验证的把手

本篇是一张表，不产生可直接运行的命令。可以对照的实物有三处：

1. **原语列的可调用性**：表里每个「项目侧原语」都对应模块库里的一个可调用模块（`mods/` 下的 `env` / `entity.place` / `component.attach` / `element.build` / `level.mount` / `graphgen.build` / `terrain.patch` 等），模块是否已实现、自测是否通过，可逐个核对。
2. **证据等级列的自洽**：把任何一行的「字节位置」拿去真实文件里复读，看它是不是真在那一格；把任何一行的「人工核验」拿去日志里查，看那次实测记没记。
3. **「推断」列的可升格性**：每一条「推断」都能配一次单变量实验。实验做完，它要么升格、要么被证伪——这张表的价值，正在于这些格子是可动的。

## 未确定项

- **表本身的完整性**：这张表覆盖的域不全（特效、道具、技能、职业、界面控件等域尚未系统地进表），已进表的域也可能漏行。这是一份可增补的活表，不是终版。
- **项目侧原语的收编进度**：多条映射的字段已定案，但对应模块尚未建（表里标「待建」）。从「字节实证」到「有原语可用」之间还隔着一次模块化。
- **证据等级会随版本变**：左岸字段随游戏版本变（**推断**），一次更新可能让某些「字节实证」的行失效；具体哪些字段在哪些版本间变过，尚无一价清单。

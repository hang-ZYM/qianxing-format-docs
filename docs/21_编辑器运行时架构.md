# 21 · 编辑器运行时架构（活体行为定律）

> 证据：[A][J]。前面各篇描述格式与静态行为；这一篇描述编辑器**作为活体系统**的行为——它何时读数据、从哪读、图的身份是什么、内容如何进如何存。做生成器、校验器或任何自动化工具之前必读。
> 版本绑定：以下行为在 CN 7.1 编辑器实测；混淆名与内部结构随版本变化（见 README 诚实声明 2），行为定律本身预期跨版本稳定，但需按 06 篇方法复核。

## 1. 生命周期 = 关卡会话 [J]

编辑器不是独立常驻程序：**进关卡拉起、退关卡自动退出**。

推论：

- 不存在"离线打开编辑器"的形态——一切针对活体编辑器的研究与工具都必须在关卡会话内进行；
- 每次进关都是全新实例，没有跨会话的内存状态；
- "关卡打开编辑器，不是编辑器打开关卡"——编辑器是游戏在本局会话内的附属工具。

## 2. 数据入口唯一律 [A]

关卡内容进入编辑器的**唯一时机**是进关卡建立连接后的一次性推送。实测时间线（退关重进循环，文件监视 + 日志双路）：

| 时刻（相对连接） | 事件 |
|---|---|
| 0 | 编辑器拉起并与游戏侧建立连接 |
| ~0.6s | 清场开始/结束 |
| ~0.9s | 装载状态 0→1 |
| ~2.6s | 状态 1→2→3，关卡就绪 |

关键事实：

- **装载全程编辑器对本地 .gil / .gis 关卡文件零读写**（文件系统监控实证，读与写皆无痕迹）；
- 主 .gil 是**游戏侧**读取的数据（推送的数据源之一）——这就是"修改文件 + 退关重进"能生效的路径：游戏侧读到 → 下次推送带进新编辑器实例；
- 编辑器没有"运行中重读数据"的官方机制——数据只在进关卡时进入一次。

> **与 docs/02 §1 的术语对账**：02 篇说分片文件是"编辑器加载图定义的来源"，准确含义是分片是**推送链路的数据源**（游戏侧消费），编辑器进程本身不做文件读取。v1.3 已在 02 篇补注。

## 3. 云端权威 [J]

- 地图的"户口"在云端，本地 `Player.gip` 只是列表缓存（02 §1）；
- **内容级云端优先判例**：重进关卡时，云端版本会覆盖本地文件版本（实测：本地当日旧版被云端版替换）；
- 结合 02 §2（完全退出游戏才落盘）——本地三文件是"最后已知状态"的镜像，**不是权威副本**。

推论：本地未上传的修改在退关重进时可能被云端版覆盖。修改要么在同一会话内完成验证，要么先走官方保存（上传）再退出。

## 4. 树可见性 = 拉取制 [A]

编辑器的图树（分类树、筛选树）**不是事件推送制**——内容变化不会自动刷新树。

- 树在一个刷新动作发生时**重建**（实测：触发刷新后叶子从 0 → 12）；
- 推论一："树里看不见" ≠ "库里不存在"。第三方修改库内容后必须先触发刷新再下结论；
- 推论二：筛选树是纯视图，随所属窗口生灭。

> **版本史注记**（诚实记录一次翻案）：早期我们持有"树可见性 = 实体挂载"的理论（所有可见图恰好都是实体挂载图），后被实测推翻——判别因素不在挂载，在 §5 的图身份链。相关性≠机制，此案已入本项目正误账。

## 5. 图身份模型 [A]

一张图的运行时身份由两层构成：

```
图文档（图内容 + 所属关卡引用）
   └── 包装引用（编辑器选图/开图时经它解析）
```

- **图名只存在于视图层**——全局对象扫描零命中：名字不在内容数据里，改内容数据改不到图名；
- 叶子持有的画布引用可以为空——**图内容与活画布是两回事**（见 §6）；
- 缺包装引用的图文档：库里有、树不认——经非官方路径提交的内容必须补齐身份链才可见。

## 6. 工作画布 = 单文档槽位 [A]

- 图**被打开编辑时**才有活画布；编辑器同一时刻只有一个工作画布（单文档模型）；
- 未打开的图，内容安静地躺在序列化数据里，没有活画布；
- 保存作用于当前文档；"当前打开的图"随用户交互切换——**任何工具在写入画布前必须确认目标图**；
- 行为判例 [J]：替换工作画布的内容 = 改变当前打开的图；经游戏侧保存 → 退关重进 → 内容存活（画布路径可持久化）。

## 7. 图装载粒度 = 整关 [J]

编辑器对外部内容提供的装载入口以**整关**为单位。

- 实测判例：通过该入口装载单张图 = **整个关卡内容被替换**（用户其余图被挤掉，事故实锤）；
- 推论：第三方工具更新单张图**禁止**走整关装载入口。单图更新的安全面只有两个：工作画布（§6，会话内）或文件 + 重进（§2，走游戏侧）。

## 8. 正典库模型 [A]

编辑器内存中维护一个正典库（内容注册中心），两类条目：

| 条目类型 | 数量级 | 内容 |
|---|---|---|
| 图文档 | 数百 | 图内容 + 所属关卡引用 |
| 节点定义 | 近两千 | 节点类型签名（编辑器画布上的"词汇表"） |

关键定律：**节点定义注册表在无连接时为空**——定义不是编辑器内置的，来源是建立连接时由游戏侧下发。

推论：

- 离线环境（无游戏连接）里编辑器拿不到节点定义——任何"离线复现编辑器装载行为"的尝试天然缺失这一半输入；
- 图文档带关卡引用：图不属于全局池，属于关卡（跨关移动图 ≠ 简单复制文档）；
- **库不变量判例** [J]：正典库的一致性由编辑器内部注册路径维护——绕过注册路径直接改库的内部集合，会破坏树渲染（实测：插入后树显示损坏，撤销并重启后恢复，内容零永久损伤）。第三方工具不应触碰库的内部结构。

## 9. 值路径架构 [A]

**字面值从不进入运行时模型。** 装载只构建结构（节点/引脚/连线），值由读取器在需要时从原始数据现读。

推论：

- **结构判定与值判定是两个独立问题**——结构合法不保证值形态被接受，值错误也不表现为结构差异；
- 校验体系必须分面设计（结构面 + 值形态面，见 06 篇）；
- 这解释了一类"离线全对、装载被剥"的事故：病灶在值形态层，结构校验根本看不见它。

## 10. 静默全景的运行时含义 [J]

02 §3 定律 1（静默降级）在装载期的完整展开：

- 装载对不合规节点**逐个静默跳过**——不中断、不计数、不留任何痕迹；
- 判例：一份通过文件级校验的病件，装载后节点被剥离——**文件级判定放行了节点级病灶**。判定粒度必须到节点级（装载前后节点数对照是唯一可靠的差分手段，见 06 篇）;
- "编辑器亲述原因"不存在——错误定位没有日志可查，只能靠差分。

## 本篇定律速查

| # | 定律 | 一句话 |
|---|---|---|
| 1 | 关卡会话 | 进关拉起退关退出，无离线形态 |
| 2 | 数据入口唯一 | 连接后一次推送（~2.6s）；装载期零文件读写 |
| 3 | 云端权威 | 重进时云端版覆盖本地；本地是镜像不是权威 |
| 4 | 拉取制 | 树不自动刷新；看不见 ≠ 不存在 |
| 5 | 图身份两层 | 图文档 + 包装引用；名字只在视图层 |
| 6 | 单文档画布 | 只有当前打开的图有活画布；写前确认目标 |
| 7 | 整关粒度 | 单图装载入口 = 整关替换，禁用 |
| 8 | 正典库 | 节点定义连接时下发，离线为空 |
| 9 | 值不进模型 | 结构与值是两个独立判定面 |
| 10 | 装载静默 | 逐节点跳过零痕迹；判定必须节点级差分 |

# 任务分解：步序、判据、权威状态

> **读者为什么需要知道这个** —— [06](06_模块化.md) 给了"可调用的单元"，这一篇给"怎么把它们串成一次创作"：一次创作被拆成什么、每步怎么算完成、失败之后退到哪里、状态存在哪。里面有一条立场是本文的核心：**文件不是真相，已验证的操作日志才是。** 不读它，你会以为产物（那份 `.gil`）是权威——而它会变、会坏、会丢。

**前置**：[03 两岸一桥](03_两岸一桥.md)、[06 模块化](06_模块化.md)。日志文件与版本目录的落点细节见 08 状态（尚未写出）。

## 一、一次"创作"被拆成什么

### 任务的定义：每个任务 = 一次模块调用

分解的产物不是"待办清单"，是一串**模块调用**。三步循环：

```
分解   用户意图 → 子任务序列           （编排器的工作）
执行   每个子任务 = 调用一个已验证模块   （模块库的工作，见 06）
沉淀   反复出现的子任务 → 固化为新模块   （库随创作成长）
```

两级粒度：

- **功能级**（编排单位）——一个用户可感知的子目标："合成一张图 / 装配进关卡 / 交付验收"。编排器（AI）在这一级工作：拆意图、排顺序、读结果、定下一步。
- **操作级**（原子操作）——每个操作 = 一次模块调用，语义单一，带完整契约四要素。

### 为什么每个任务必须落到一次调用

因为**编排器只组合、不实现**：它不得现场发明操作，库外需求要先把模块造出来再调用（见 [06](06_模块化.md) 第四节）。没有这条，能力会以"这次先手动搞一下"的形式流失掉，下次还得重来。

### 一个实例

意图"做一个进图打印 `[hello_loop]` 的关卡"，编排器产出并逐步执行（形态取自内部设计书的垂直切片实例，调用名对齐实现）：

```python
r1 = graphgen.build(logic=GraphLogic(...), name="hello", guid=0x40000001)
     # 后验 = 门禁四连 → PASS，关卡 v1
r2 = level.mount(graph_gis=r1.artifact, host_guid=0x41400001,
                 graph_guid=0x40000001, category=20000)
     # 后验 = 出口校验 V0-V7 → PASS，关卡 v2
v  = level.judge(expect_print="[hello_loop] 圈活了")
     # 三相轮询：等导入 → 等 .gia → 在 .gia 里找那句打印字节
```

三次调用，三个判据，三种耗时的验收。步间不是"走完再说"，是每一步都拿到 `Result` 再定下一步。

## 二、权威状态 = 已验证的操作日志

### 为什么文件不是真相

产物（那份 `.gil`）不配当权威状态，因为它会变、会坏、会丢：

- **会被平台改写**——导入器重编号标识符是常态，同一份产物从平台出来已经不是进去时的字节；
- **会损坏、会丢失**——它就是个文件。
- **日志不会**——只追加，不被任何一方改写。

立场一句话：**怀疑"现在这份关卡对不对"，永远去查日志，不去读那份 `.gil`。**

日志是 `state/oplog.jsonl`，一行一条，只追加，字段固定：

| 字段 | 含义 |
|---|---|
| `seq` | 单调递增序号（取号靠读文件尾，不全量扫） |
| `ts` | 时间戳 |
| `module` | 哪次模块调用 |
| `args` | 参数摘要（repr，截断 160 字符；机器位置脱写） |
| `kind` | `ok` / `rejected` / `precondition` / `error` 四种 |
| `ok` | 是否成功 |
| `checks` | 校验明细，形如 `[(检查名, PASS/FAIL/TRIVIAL/PENDING-ANCHOR)]` |
| `version` | 这次调用落在哪个版本号上 |
| `error` | 失败原因（失败条目才有） |
| `secs` | 耗时 |

### 由此得到三个性质

**① 做过的不重做 = 读日志比对。** 编排器要"已完成清单"，不是问文件，是 `log.query(ok=True)` 把成功条目捞出来。同一批参数的成功条目已经在日志里，就不该再调一次。

**② 撤销 = 回退指针。** 回滚不产新版本、不删存档，只是把指针回拨：`current.json` 里记着 `{version, op_seq, updated_ts}`，`level.rollback(level_name, to_version)` 把 `version` 改成目标版。版本文件原样留着，所以"撤销"是可再撤销的。前置校验挡住两种非法回拨：目标版不存在、目标版就是当前版。

**③ 可复现 = 重放日志。** 日志记全了每次调用的模块、参数、验收结果、版本号——理论上从任意空状态按序重放这串调用，可以重建产物，也能事后审计"这个字节是谁写的"。

### 代价（这一节必须写出来）

权威状态不是白拿的，账有三笔：

1. **要维护日志**。每次调用都要写，且取号要单调（`_last_seq` 从文件尾读最后一条的 `seq` 再加一）。日志是这套体系里唯一每次操作都必须写对的东西——它自己出问题，前面所有性质一起失效。
2. **要保证重放幂等**。日志只追加、从不修改历史条目；但"重放等价于原执行"要求每个模块确定性、且版本号只由 `current.json` 决定。**当前没有防止手动改产物的闸**：若有人绕过模块直接改了一份 `.gil`，日志仍指向旧版本，重放就不再等价（待补：产物篡改检测）。
3. **重放引擎未实现**。日志是"可重放"的**数据结构**，但把日志真的读成调用序列并跑起来的引擎还没写（P2 计划项）。当前"可复现"这一条靠的是 IR 一键重建（同一份 IR 重跑一遍得到同样的字节），不是日志重放。

还有两笔小的，如实记下：

4. **参数摘要截断 160 字符**，长参数（比如大块载荷）无法从日志精确重建（**推断**：这是重放引擎迟迟未落地的原因之一）。
5. **日志脱写机器位置**（状态根 / 仓库根 / 家目录 → `<state_root>` 之类标记），所以日志可审计、可跨环境看，但不携带本机绝对路径——**跨机重放需要额外的路径映射**（待补）。

## 三、步序与判据

### 一步怎么算"完成"

一步的完成判据 = 该模块后验取的验收级。判据分三种形态：

| 形态 | 判据长什么样 | 谁判 | 例 |
|---|---|---|---|
| **看字节** | 机器可读的格式/结构断言 | 机器，零人工 | `roundtrip`（往返一致）、门禁四连、出口校验 V0-V7、地形块数交叉核对 |
| **人工核验** | 人在编辑器 / 实机里眼看 | 人 | 少数机器判不了的表现（如某些视觉件的人工目视检查） |
| **实机试玩** | 运行级行为 | 人动作 + 机器判决 | `level.deploy` → 导入试玩 → `level.judge` 在 `.gia` 里找打印字节 |

判据要**预写**：试玩之前先定"看到 X = 判 Y"。`level.judge(expect_print="[hello_loop] 圈活了")` 就是预写的判据——那句打印字节在不在，判定是二值的，不靠事后解释。

### 每步独立可验的理由

不是项目管理习惯，是粒度差直接逼出来的（见 [03](03_两岸一桥.md) 第三节）。一个愿望在字节层可能是四个独立旋钮，"一次改四个、没生效"时你不知道是哪个错了；把愿望拆成"改一个字段、验一次"的步骤，错在哪一步就定位到哪一步。这也是单变量原则在任务分解里的落点：**一步一个变量，一步一次判定**。

### 可达性

后验取**该操作可达的最高级**，判不了的级要诚实声明，不美化。模块库用状态位承载这件事：`PASS` / `TRIVIAL`（纯信息）/ `PENDING-ANCHOR` / `PENDING-S1` 如实透传。`level.mount` 的出口校验行就是原样解析进 `Result.checks` 的，`[INFO]` 归 `TRIVIAL`，其余状态不加工。

## 四、编排

### 输入与输出

- **输入**：用户意图 + 当前状态。当前状态 = 日志尾部 + 当前版本号（`current.json`）+ 已完成 / 已失败两份清单。
- **输出**：**下一批**模块调用（一次一步，步间拿 `Result` 修正）。

### 怎么从日志决定下一步

一个具体的判断流程：`log.query(module=..., ok=True)` 取某域的成功条目 → 参数命中的说明已做过，跳过 → 找未完成的下一步 → 调用 → 读回 `Result.ok` / `Result.checks` / `Result.version`，再定再下一步。判据全在 `Result` 里，编排器不需要去读产物本身。

### 失败怎么退

| 失败 | 机制 | 退法 |
|---|---|---|
| 前置不过 | `PreconditionError` | 换路：改参数或换模块，**零损失** |
| 后验不过 | 自动回滚（版本指针未动）+ 计失败 | 重试；连 4 次 → `ConsecutiveRejectError` → 必须换路 |
| 运行级判败 | `Verdict.passed = False`，产物**不回滚** | 判决 + 观察数据回流 → 分解出修复调用 |

后验失败之所以只损失一步：版本制下每次通过落一版，回滚是指针回拨，坏的后验结果根本没落成版本。运行级判败不回滚，是因为产物本身有效（关卡是能导入、能玩的），问题在行为，得改而不是退。

### 编排器的边界

只组合、不实现；失败履历回流；常见调用序列沉淀成模板后优先复用。编排器本身是一次只生成一批调用的循环，它的载体不在本仓库公开范围（待补），本篇只规定它吃 `Result`、吐调用这件事。

## 五、和左岸的接缝

任务序列最终要落到左岸**具体的关卡段**上。这是右岸任务与左岸字节的接缝，也是 [04 对齐](04_对齐.md) 那张表的入口：

| 任务（模块调用） | 落到左岸的哪一段 |
|---|---|
| `graphgen.build` | 产出一张 `.gis`；经 `level.mount` 落进 f10 图库条目 + f6.f13 挂载条目 + f6 树4 叶 |
| `level.mount` | f5 关卡实体宿主（`0x41400001`）+ f6.f13 挂载 + f6 树4 叶 + 实体注册面 |
| `entity.place` | f5 实体条目 + f6 树 tab3 叶（怪物另需 0x408 段号位） |
| `terrain.patch` | f7 地形第一组地块 |
| `component.attach` | 目标实体 f5/f6/f7/f8 槽的组件条目（cid → 载荷字段） |
| `env.set` / `env.direct` | f15 资产库 tcode26 条目 + f75 参数块（含天气配置与雾）+ f6 树 cat56 注册 + f11.f1 关卡时间 |
| `element.build` | 资产层 `.gia` 元件方言（元件段） |
| `asset.package` / `asset.deploy` | `.gia` 资产包（游戏导入目录） |

一个任务落在左岸通常**不止一段**——这就是 [03](03_两岸一桥.md) 说的"右岸一行，左岸可能是一整天"。完整对照见 [04 对齐](04_对齐.md)。

## 可验证的把手

1. **日志本体**：`state/oplog.jsonl`，一行一条 JSON，字段见本文第二节的表；`kind` 四种值都能在真实跑过的会话里找到。
2. **指针**：`levels/<名>/current.json` 的 `version` / `op_seq` 字段——"撤销 = 回退指针"就是改这两个数。
3. **回滚与查询**：`mods/state.py` 的 `level.rollback` / `log.query`（`log.query` 自身 `readonly=True`，不落日志、不碰版本）。
4. **一个真实序列**：垂直切片实例的操作日志序列（`mods/MODULES.md` 记 P0 执行 seq1-6，含一次运行级判决），见该文件末段。
5. **判决三相**：`level.judge` 的相1（等新地图，镜像基线快照）→ 相2（等新 `.gia`）→ 相3（在新 `.gia` 里找 `expect_print` 字节）——判据是字节，不是自述。

## 未确定项

- **日志重放引擎未实现**：本篇说的"可复现"目前是设计性质 + IR 一键重建，真正的"读日志重放"是 P2 计划项（待补）。
- **无产物篡改检测**：绕过模块直接改 `.gil` 时，日志不会察觉；重放等价性因此有前提（待补）。
- **参数摘要截断**：`args` 截断 160 字符，长参数不能从日志精确重建（推断）。
- **跨机重放**：日志脱写机器位置，跨环境重放需要路径映射层（待补）。
- **状态根位置随环境**：公开仓默认 `<仓库根>/_state/`（`.gitignore`），开发树默认自有路径，两者都可用 `QXYV2_ROOT` 重定向——同一条日志在不同根下不可直接互认。
- **多域编排未实现**：本文的实例是单域垂直切片（图 → 关卡 → 判决）；"搭一个区域"这种跨多域编排还在 P1 计划里（待补）。
- **编排器载体未见于本仓库**：编排循环的实现载体（内部 loop 壳）不在公开仓 `mods/` 中，本篇只规定它的输入输出契约（待补）。

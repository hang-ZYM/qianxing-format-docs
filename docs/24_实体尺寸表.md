# 24 · 实体尺寸表（W / D / H 全量测量数据）

> 证据：[A]（本地资产实测 + 用户面板标定三重验证）。表本体是机器可读的 JSON，收在仓库 `data/` 目录；本卷是它的说明书——数据从哪来、怎么读、怎么用。
> 单位：**米**。数据基于 7.x 本地游戏资产提取；实体更换模型时数值随之变化。

## 1. 这是什么

每个摆件类实体（建筑/装饰/景观/机关……）的**视觉基准包围盒**——宽(W) × 深(D) × 高(H)，scale=1 时的原始尺寸。做场景布局计算（间距、对齐、碰撞预估）时查这张表。

| 数据文件 | 条数 | 键 | 值 |
|---|---|---|---|
| `data/prefab_sizes_full.json` | 2240 | asset_id | `{name, mesh, W, D, H, category, confidence}` |
| `data/beyd_mesh_bounds.json` | 2771 | mesh 名 | `{W, H, D, verts}`（网格顶点数） |

两张表以 `mesh` 字段为连接键；prefab 表是"实体视角"（带中文名与分类），bounds 表是"网格视角"（覆盖更全，含未被 prefab 引用的网格）。

## 3. 数据怎么来的（方法）

1. **提取**：用社区工具链（HoYoStudio 系，含 AnimeStudio 的 Blb 块解密移植）从本地游戏文件中枚举并导出千星（Beyd 系）视觉网格；
2. **测量**：对网格计算视觉包围盒（不导出资产本体，只留数值）；
3. **配对**：asset_id → mesh 的映射用**图标名配对法**——prefab 元数据的 icon 字段编码了网格身份（如 `Prop_Chair_04`、拼音系 `Shugui`），与网格名 `Beyd_Object_<token>_Vo` 直接对上；部分 Struct 系图标名甚至编码了尺寸（`Window_50_50_5` = 5.0×5.0×0.4m）；
4. **验证**：与用户在编辑器面板直读的标定值三重对照——木质矮柜 3.317×1.122×1.191（测量）vs 3.311×1.123×1.193（面板），**误差 6mm**。

## 4. 怎么用

### 4.1 实际尺寸 = 基准 × scale

表给的是 **scale=1 的基准尺寸**。实体被缩放后的实际尺寸：

```
实际W/D/H = 表值 × scale.x/y/z
```

scale 的序列化落点与旋转换算见 docs/11（变换缩放）。目标尺寸已知时，scale = 目标 ÷ 基准，可精确计算。

### 4.2 与地形网格配合

地形格距 5×5m、层高 2.5m（docs/17）——布局时的换算示例：墙板基准 5.0m 宽正好一格；24m 车厢每侧 24÷5 ≈ 5 块。

### 4.3 W / D / H 的方向含义

W/D/H 为网格自身包围盒的三个轴向；实体旋转（Y 轴弧度，docs/11）后占据的空间要按旋转角换算 W/D（如 90° 互换）。高对称件（方桌、地毯）无方向歧义，长条件（墙、桌）要注意。

## 5. 诚实边界

- 数值是**视觉包围盒**，非碰撞体尺寸——两者的差通常很小但不恒为零；
- 部分带动画/摆动的实体，包围盒取的是静止基准姿态；
- 数据绑定提取时的资产版本，官方更新模型后需重新提取；
- 怪物与六角色借形实体不在表内（见 §2 缺口），不要对它们查表外推。

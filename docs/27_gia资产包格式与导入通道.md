# 27 · .gia 资产包格式与导入通道

> 证据：[A] 字节实证（用户导出件逆向 + 三批自建包 207/258/264 件的导入实测，2026-10-03/04）
> 状态：**通道已规模化验证**——位置/缩放/染色全保留；旋转需按本卷 §4 度数定则书写。
> 意义：实体交付不经过编辑器（编辑器无法导入），是"AI 产出 → 游戏内导入"的官方通道。

## 1. 定位

`.gia` = 资产组合包（AssetBundle），用于**把一批实体打进一个官方文件、在游戏内导入到地图**。
与 `.gil`（关卡文档）/`.gis`（图分片）同族容器（见 01 卷），type=3。

**通道特性（实测判例 [J]）**：
- 导入入口在**游戏内**（地图管理界面），编辑器内导入不了
- 实体的位置/缩放/旋转/染色**全部随包携带**（与 .gil 实体字节同构，§3）
- **没有官方撤回**：导入直接写入地图云端存档；编辑器 UI 字符串只有"导入"无"撤销"
- 同 guid 重复导入是否替换：**未测**（开放问题 §7）

## 2. 容器层

标准 20B 头 + protobuf + 4B 尾（01 卷），`file_type=3`。

## 3. 载荷结构（protobuf 顶层）

```
f1 × N: 实体包装 {
    f1: 引用 { f2: 1 (类型=实体), f3: 2 (子类型), f4: guid }
    f3: 实体显示名 (UTF-8)
    f5: 3 (常量)
    f12: { f1: 实体完整字节 }   ← 与 .gil f5 里的实体消息完全同构
}
f3: 元数据字符串 "账号-时间戳-地图id\文件名.gia"（时间戳=unix 秒）
f5: 版本 "7.1.0"
```

- 实体字节即 .gil 实体：六槽组件模型（03 卷），位置组件 comp1 的 `f11.{f1位置,f2旋转,f3缩放}`、
  染色 comp22/f32 四件套（11 卷）全部原样生效
- guid 建议取 0x404 段（机关/gadget），与地图现有实体不冲突

## 4. 旋转度数定则（本通道第一坑）★

位置组件 `comp1.f11.f2 = { f2: fixed32 float }` 的值是**度数**：

| 证据 | 内容 |
|---|---|
| [A] 官方 RPG 模板 | 被编辑器转 90° 的石墙（20001340）字节值 `90.0`；另有 -64°/16°/91° 任意角 |
| [K] schema 骨架 | 10 卷 DecorationItem 字段名即 `yaw_deg`（上游 gia.proto）——**库内早有答案，先查库** |
| [J] 反面判例 | 自建 258 件包按弧度传 π/2→1.5708，游戏读作 1.57°，全部实体旋转归零（城墙不转） |

- `comp5.f15.f2`（四分转索引）只是编辑器缓存标记：官方数据自相矛盾（16° 的件也挂 1），
  非权威，不依赖
- 设计文档若用 π 记法，出包前必须 弧度×180/π

## 5. 构建配方（工具已固化）

| 工具 | 作用 |
|---|---|
| `M4_组件/gil_to_gia.py` | .gil 实体区 → .gia（基础转换） |
| `M4_组件/build_gia_m4.py` | 设计图 → synth 合成 → 双包（全量 + 区域小包） |
| `M4_组件/design_parse.py` | 设计图解析（镜像/±简写/紧凑行 + 弧度→度 + 染色族映射） |

要点：元数据里的地图 id 要写目标地图；版本必须 `7.1.0`（7.0 件会被升级器重写）；
滤掉地图默认实体（关卡实体等 11 件）避免导入重复。

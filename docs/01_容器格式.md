# 01 · 容器格式（.gil / .gis / .gia）

> 证据：[A]（全样本字节实证，跨 5.x 多版本）

## 1. 文件族

| 扩展名 | 容器类型码 | 用途 |
|---|---|---|
| `.gil` | 2 | 关卡主文件 / 图定义文件 |
| `.gis` | 2（内容为分片） | 关卡分片（slice） |
| `.gia` | 3 | AssetBundle（导出/分享件，可含多资源） |
| `.gip` | 1 | 玩家/会话数据 |
| `.gilh` | —（同为806魔数容器） | 地图级实体索引缓存 |
| `.gir` | — | 已发布关卡运行时数据 |

## 2. 容器布局（20B 头 + protobuf + 4B 尾）

```
[0:4]   payload_total   大端 uint32   ★铁律 = 文件总大小 - 4
[4:8]   version         大端 uint32   = 1
[8:12]  magic           大端 uint32   = 806 (0x326)
[12:16] file_type       大端 uint32   1=gip, 2=gil/gis, 3=gia
[16:20] proto_len       大端 uint32   = protobuf 载荷长度
[20:20+proto_len]       protobuf 消息（见 docs/03）
[末4B]  trailer         固定 00 00 06 79
```

**最容易踩的坑**（实证判例）：`payload_total` 写错（比如写成 proto_len + 20）会导致整个文件被拒绝。正确值 = `20 + proto_len + 4 - 4`。

## 3. 与 protobuf 的接缝

- 容器内是一段**普通 protobuf 消息**，字段号与语义见 `docs/03_数据模型总表.md`。
- `.gis` 分片的 protobuf 顶层以 **f2 字段承载"分片内容消息"**（level 文档的主体）；
- `.gil` 主文件的 protobuf **整体就是同一个文档消息**（无 f2 包裹）——两者共用同一消息结构（行为学验证：把主文件整体与分片 f2 载荷分别喂给全部 2100+ 候选 proto 类，唯一守恒者是同一个类 [J]）。

## 4. 容器级校验行为 [J]

- 头部长度与实际不符 → 整文件拒绝（不进入 protobuf 解析）。
- protobuf 载荷截断 → 解析异常 → 内容被**静默丢弃**（见 docs/02 §静默降级）。
- 尾饰错误 → 拒绝。

## 5. 往返验证铁律 [J]

任何"解析 → 修改 → 重写"的容器手术，动手前必须先确认**往返一致性**：

```
encode(parse(x)) == x
```

往返不成立 = 你的解析器对该文件有理解偏差（漏字段、错嵌套、方言差异），此时做出的任何修改必然引入损坏。嵌套长度前缀（外层容器的 proto_len、内层各消息的长度字节）会级联受影响——局部字节替换不可靠，改用全递归重编码（方法与实例见 docs/22 §4）。

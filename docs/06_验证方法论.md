# 06 · 验证方法论（给其他封闭 UGC 平台的研究者）

> 本项目所有结论都来自可复现实验。这一篇把方法抽象出来——它同样适用于其他带私有格式的 UGC 编辑器（Roblox、各类关卡编辑器）。

## 1. Oracle 思路：让平台的代码当裁判

编辑器本体（哪怕被混淆壳保护）通常可以在自建宿主里以反射方式加载。只要能：

```
解析(payload) → CalculateSize → 与输入长度比对
```

就得到一个**零漂移**的离线校验器，三级判定语义：

| 判定 | 判据 | 平台行为 |
|---|---|---|
| 恒等接受 | size == len | 原样保留 |
| 规范化 | size < len | 接受，保存时剥除冗余 |
| 丢弃 | 解析异常 | 内容消失，无提示 |

发现类真身的方法（当名字被混淆时）：**行为学暴力**——把真实载荷喂给全部候选消息类，守恒者即真身（本项目用它在 2138 个类中唯一定位了主文档消息类）。

## 2. 金样本纯净性（最重要的纪律）

> **永远不要从"平台保存过的第三方内容"归纳格式规则。**

多数编辑器保存时对既有内容"只存不改"——你写入的错误字段会被原样存回。用这种样本验证自己的规则 = 循环论证。本项目曾据此把"引脚索引 1 基"的错误结论保持了两天，直到让用户在编辑器里**从零原生创建**一个对照样本才翻案。

正确做法：归纳规则用的参照必须是平台原生创建的内容；第三方修改过的文件只用来研究"平台如何对待第三方内容"。

## 3. 单变量对照 + 二分定位

- 任何"显示不对/内容丢失"问题，先做**全量还原对照**（恢复到已知好状态，排除自己的改动）再谈其他；
- 多个可疑修改同时存在时，用**逐级二分**（只改 A / A+B / A+B+C...）让裁判逐级判定，肇事修改自动浮出。

## 4. 落盘协议

搞清楚"什么时候写盘"再读文件：本项目实测该编辑器**保存→云端、退出编辑器→不落盘、退出游戏→落盘**。在错误时机读盘会得出"保存丢了"的假结论。

## 5. 证据分级

每条结论标注来源强度：字节实证 > 可复现判例 > schema 注释推断 > 目录数据。含混时宁可标"待验证"——过度声明的完成度是知识库最大的债。

## 6. 边界诚实

离线校验器能判**解析层**（字节是否被接受/规范化），判不了**语义层**（UI 如何解析引脚对位、类型匹配）。语义层的静默丢失（连线消失、值不显示）只能靠原生样本对照或在体观测（挂载平台加载管线）捕捉。说清楚工具的边界，和工具本身一样重要。

> 本项目的活体行为定律（docs/21）部分通过编辑器进程内观察获得；观察方法不在本仓库发布范围内（README 诚实声明 5）。

## 7. 七条元律（全部由翻案判例喂养）

研究封闭平台最容易犯的不是技术错，是**方法错**。以下七条每条都对应至少一次真实翻案：

| # | 元律 | 一句话 | 血案 |
|---|---|---|---|
| M1 | 上下文限定 | 任何"死路/通路"结论都要带通道与前提——官方导入的死路可能是其他路径的坦途 | 一度判死的伪造路径，换通道后畅通 |
| M2 | 推理绿≠实证绿 | 静态校验全绿不等于运行被接受；实测只做终审 | 推理完备的构造被平台静默拒收 |
| M3 | 单样本不定常量 | 一个样本归纳出的"规则"必须两样本或一回合验证后才算数 | 多个"常量"后来发现是样本巧合 |
| M4 | 跨版本禁外推 | 旧版本的格式形态不能外推到新版本——假设先过自家存档对照 | 旧版蓝图形态在新版上五轮绕路 |
| M5 | 拼装≠同源 | 手工拼装的完整字节 ≠ 同源整体的克隆——平台的完整性校验按整体血缘 | 满配字段的手拼件被拒，整体克隆通过 |
| M6 | 分层判定 | 见 §8——分层判错，方法全错 | 直注三连败 |
| M7 | 静默降级 | 三层（编辑器/装载/运行时）对内容问题全部静默——错误唯一表达是"东西不见了"（docs/02 定律 1） | 校验全过的病件装载后被剥 |

## 8. 三层认识论（M6 的展开）

**每类知识有不同的最高证据，用错方法研究就翻车**：

| 层 | 典型问题 | 最高证据 | 纪律 |
|---|---|---|---|
| 平台/客户端层 | 容器、序列化、保存行为、导入器、UI 渲染 | **读机器**：反编译、内存快照、官方样本 | 禁止用测试回答这层问题——读一次=永久 |
| 服务器/运行层 | 执行语义、触发判定、变量同步 | 官方示例 + 社区数据 + 实测**三角定位** | 唯一允许实验的层；先穷尽可读源，实测只兜底 |
| 视觉/体验层 | 好不好看、像不像 | 用户验收 | 不要用代码审美替代用户眼睛 |

核心教训：直注三连败是平台层问题（源码里写着答案），却用试错法回答——**分层判错，方法全错**。反之，执行语义的实测是运行层知识的合法途径，那不是浪费。推论：囤齐"读机器"资产之后，**再猜就是懒**。

## 9. 病件工厂（对抗测试集）

校验器自己也需要被验证——方法：**故意制造病件**。

- 为每类已知病灶形态构造一个最小病件：泛型值缺包裹、类型码非正典、缺内核定位符、容器截断、重复 id……
- 喂给校验器，要求**好件全放行、病件全拦截、分级正确**（丢弃/规范化/恒等，docs/02 定律 2）；
- 事故形态要复现进测试集：本项目曾出现"双校验全过的构造，装载后被静默剥离"——此类事故的每个形态都应固化为永久病件。

病件工厂让校验器的回归变成零成本——改一行判定的代码，跑一遍全语料。

## 10. 判定粒度（文件级放行了节点级病灶）

- 文件级判定（"解析成功/失败"）对**节点级病灶全放行**——一个坏节点不拖垮整文件解析，但装载后它单独被剥（docs/21 §10）；
- 实测判例：一份文件级校验全过的病件，装载后节点消失。**判定必须到节点级**：装载前后逐节点存活对照（节点数 + 逐节点比对）是唯一可靠的差分手段；
- 与 §9 组合使用：病件按节点级断言写进测试集，粒度对齐病灶粒度。

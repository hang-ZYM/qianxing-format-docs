# 千星奇域数据结构文档

> 把千星奇域（《原神》的用户创作系统）这套封闭游戏的数据格式读懂，并把它变成可复用的工具与方法。
> 仓库分两侧：**左岸**处理那个封闭系统的数据格式，**右岸**处理我们自己的关卡项目，中间靠**对齐**连着。

## 这是什么

千星奇域是《原神》里的 UGC（用户创作）系统。它没有 SDK、没有公开文档、没有源码：想在里面做出复杂的东西，只有两条路——手工在编辑器里点，或者**把它的数据格式读懂，然后直接生成**。

这个仓库是走第二条路的成果。它不是一本手册，而是两侧内容加一座桥：

- **左岸 · 对「游戏」的处理** —— 那个封闭系统的数据格式：容器、字段、组件、节点、实体、环境、地形。这部分是别人的系统，只能**发现**，不能发明。
- **右岸 · 对「项目」的处理** —— 我们自己的关卡项目：它由什么构成、怎么拆成模块、怎么拆成可验证的步骤。这部分没有唯一答案，是我们自己**设计**的。
- **桥 · 对齐** —— 右岸的每一个设计决定，都要落到左岸某个可行位置上。

一句话：**左岸是理解，右岸是设计。左岸你只能发现真理，右岸你可以创造结构。** 展开见 [docs/03 两岸一桥](docs/03_两岸一桥.md)。

## 为什么分两侧

因为这两侧的性质不同：

| | 左岸 · 对「游戏」的处理 | 右岸 · 对「项目」的处理 |
|---|---|---|
| 对象 | **别人的**封闭系统 | **我们自己的**关卡 |
| 能动性 | 只能**发现**：读懂它、按它的规矩写 | 可以**发明**：怎么设计、怎么拆、怎么组合，自己定 |
| 动作 | 译解 / 适配 | 设计 / 构造 |
| 变化速度 | 字段随游戏版本变 | 架构相对稳定 |

混在一起写，读者会分不清哪些是"世界的事实"、哪些是"我们的选择"——这两件事的可信度与可改动性完全不同。所以左岸的结论标证据等级（它要么对要么错，可以用字节与实机去判），右岸的主张给理由（它不是真假问题，是好不好用的问题）。真正难的也不在两端，而在中间那座桥：右岸一个愿望，落到左岸往往是一整串字节操作。

> 本节为门面简明版；**两侧性质对照表的权威版本见 [docs/03 两岸一桥](docs/03_两岸一桥.md) 第二节**。

## 能干什么

**读得懂** —— 世界的数据格式。三个容器、六槽实体模型、节点与组件全表、地形与路径系统，都按字段与字节位置整理成可查的数据字典。
证据：[`手册/`](手册/README.md)（32 篇左岸数据字典，索引见其中 README）。

**用得动** —— 一套工程方法。把复杂创作切成有独立校验器的**域与模块**（[docs/06 模块化](docs/06_模块化.md)），再把一次创作拆成一步一次调用、每步有判据的**任务序列**（[docs/07 任务分解](docs/07_任务分解.md)）。模块库在 [`mods/`](mods/README.md)，全部纯离线：不碰游戏进程，接触面只有"往导入目录放文件"与"读游戏写出的日志"。
证据：[docs/06](docs/06_模块化.md)、[docs/07](docs/07_任务分解.md)。

**查得到** —— **「游戏概念 ↔ 字节位置 ↔ 项目侧原语」对照表**（[docs/04 对齐](docs/04_对齐.md)）。
这是全仓最实用的一页：把"我想要什么"翻译成"在游戏的哪个字段、用哪个模块去动它"，每一行还标出它**卡在哪一格**（字段已知且有模块 / 字段已知但无模块 / 字段还未知）。

随仓库还附一条工具链：`qxfmt` 做容器读写、保序字节手术、图合成与格式校验，三条命令离线合成一张合法关卡图。见 [QUICKSTART.md](QUICKSTART.md)。

## 开放范围

这个仓库**开一部分、不开一部分**，边界是明确的：

- **开**：世界的事实（左岸）、方法（右岸的工程层）、可独立使用的工具。
- **不开**：**关卡成品本身**（那是作品，不是方法），以及任何与编辑器进程内操作、绕过正常通道相关的手段。

关卡的设计过程会作为案例写进右岸——**讲方法，不讲成品**：会写"为了做到某个效果，试过哪几条路、为什么最后选了这条"，不写关卡文件、具体场景布局、坐标与数值表。

一句话：**开"怎么搭"，不开"搭了什么"。** 说明边界本身就是一种专业：读者知道哪些事这里不讲，也就知道该信到什么程度。

> **开放范围的权威版本见 [docs/00 设计说明](docs/00_设计说明.md) 第六节**；本节为门面简明版。

## 证据分级

本仓每一条结论都标注证据等级：**字节实证**（从真实文件里读出来的）/ **官方文档**（官方语料或编辑器界面里的原文）/ **人工核验**（人在编辑器或实机里亲眼确认过的）/ **推断**（我们的推理，尚未验证）。

不为表格好看而抹平等级：左岸的断言标等级，右岸的设计主张给理由；尚未对上的位置一列直接写"未知"，不硬凑。（`手册/` 内使用简写标记，对应表见 [手册/README](手册/README.md)。）

这是本仓最坚持的一件事。逆向类文档最常见的毛病是把推测写成事实——读者拿到一条结论，却不知道它是从真实文件里读出来的，还是作者推的。把等级标出来，读者才知道该信到什么程度。

同一条纪律的另一面是：未完成项、失败路径、试过但没成的路，照写。一份能说清"我们不知道什么、试过什么没成"的文档，比一份什么都敢说的文档可信。

> **证据分级的权威版本见 [docs/00 设计说明](docs/00_设计说明.md) 第三节 原则 3**；本节为门面简明版。

# 模块参考 · 文件侧创作模块库（mods/）

> 给人类使用者的正式参考：模块库的每个模块一节，按
> **干什么（人话）/ 函数签名 / 最小调用示例 / 它自动保证了什么 / 失败时你会看到什么**
> 五段写全。名词不懂回[概念指南](概念指南.md)；"为什么要这样设计"读
> [docs/30 任务分解与模块化方法论](../docs/30_任务分解与模块化方法论.md)。
>
> 模块库随 v2.0 发布（见 [README](../README.md) 路线图）。所有调用纯离线：不碰游戏进程，
> 不做任何注入——与游戏的全部接触面只有"往游戏导入目录放文件"和"读游戏写出的日志"，
> 以及只有你能做的两件事：**导入**和**试玩**。

## 0. 配置：状态根、游戏目录与环境变量

模块库把运行状态集中放在一个**状态根**目录（缺省是仓库下的 `_state/`，已列入
.gitignore——运行产物永不入库）：

```
<状态根>/
├── levels/<关卡名>/            ← 版本存档：v1.gil、v2.gil… + current.json（指向当前版）
├── state/oplog.jsonl           ← 操作日志：一行一条，只追加（谁/何时/参数/验收/版本号）
├── state/tmp/                  ← 装配临时产物槽（验收拒绝时零污染版本域）
├── state/assets/               ← 资产包产物（asset.package 的落盘处）
└── runs/                       ← 造图产物（graphgen.build 的 .gis 落这里）
```

环境变量一览，**全部可以不设**——设了只是换地方：

| 环境变量 | 管什么 | 不设时 |
|---|---|---|
| `QXYV2_ROOT` | 状态根位置 | `<仓库根>/_state/` |
| `QXY_GAME_EXPORT` | **游戏导入目录**（`Beyond_Local_Export/`）——两个 deploy 的落点，游戏导入界面只认这里 | 按常见安装路径自动探测 |
| `QXY_GAME_MIRROR` | **导入镜像目录**（`<账号>/Beyond_Local_Save_Level/`）——`level.judge` 第 1 相观察面 | 同上 |
| `QXY_GAME_DEBUGLOG` | **试玩调试日志目录**（`<账号>/Beyond_Debug_Log/`）——`level.judge` 第 2/3 相观察面 | 同上 |
| `QXY_GAME_SAVELEVEL` | **关卡样本目录**（与镜像同域）——`level.mount` 装配用的底座/金样本关卡从这里取 | 同上 |
| `QXY_TOOL_ROOT` | 可选的**研究工具树**（见下） | 不配置——需要它的模块前置拒绝并给指引 |

三条解析与依赖规则：

1. **优先级：调用参数 > 环境变量 > 常见默认路径探测 > 未找到。** 想临时换落点传参数，
   想整体换环境设环境变量。游戏目录的默认探测位置在你的游戏数据目录下
   （`%USERPROFILE%\AppData\LocalLow\miHoYo\原神\BeyondLocal\`，账号段按目录扫描，
   不针对任何具体账号）。全都落空时，模块抛 `PreconditionError` 并附配置指引——
   不是失败，是"环境没就绪"。
2. **工具树是可选依赖，按模块区分**：`core / state / level.mount / level.deploy /
   level.judge / terrain.patch` 零工具树可跑；`graphgen.build / entity.place /
   asset` 两链依赖本机研究工具（节点宇宙表、图装配器、实体合成器），设
   `QXY_TOOL_ROOT=<工具树根>` 后才可用，未配置时前置拒绝并如实告知。
3. **关卡样本需自备**：`level.mount` 装配关卡要拿你本机游戏目录里的两张关卡样本作
   底座与金样本对照（你自己的存档数据，仓库不附带）；找不到时报错并指路。

装好模块库后，跑一遍自带自测确认环境（分层设计：CORE 不依赖游戏目录与工具树，
FULL 走真实链路）：

```bash
python -m mods.selftest          # CORE：基础设施 + 合成件离线自测
python -m mods.selftest --full   # FULL：真实游戏目录与工具树链路
```

**自测零污染**：所有目录都可重定向到临时目录。跑自测时，真实游戏目录和真实版本
存档一个字节都不会被碰——这也是你试用任何模块的安全兜底：先给参数指到一个
临时目录，看它写什么。

## 1. 全家福

每个模块 = 一个可调用的 Python 函数。四件事内建：**前置检查 → 执行 → 后验 → 日志与版本**。
你调一次，结果只有两种：拿到一个**已通过验收的新版本**，或者**什么都没改变**并拿到原因。

| 模块 | 一句话 | 成熟度 |
|---|---|---|
| `graphgen.build` | 造一张节点图（.gis） | 已用于真实关卡交付 |
| `level.mount` | 把图挂进关卡，产出关卡新版本 | 已用于真实关卡交付 |
| `level.deploy` | 关卡版本部署到游戏导入目录 | 已用于真实关卡交付 |
| `level.judge` | 等你导入试玩，机器判判决 | 已用于真实关卡判决 |
| `terrain.patch` | 地形定点手术（层位/坡/材质/水/路径） | 离线自测 33 条通过；真实导入验证进行中 |
| `entity.place` | 放置官方实体（自动双注册） | 离线自测 38 条通过；真实导入验证进行中 |
| `level.checkpoint` | 手动落一版存档 | 基础设施件 |
| `level.rollback` | 版本指针回拨 | 基础设施件 |
| `log.query` | 查操作日志 | 基础设施件 |
| `asset.package` | 实体打包成资产包（.gia） | 离线自测 25 条通过；真实导入验证进行中 |
| `asset.deploy` | 资产包部署到导入目录 | 离线自测通过；真实导入验证进行中 |

两条公开交付链（模块怎么串）：

```
关卡链   graphgen.build → level.mount → level.deploy → (你导入+试玩) → level.judge
资产链   asset.package → asset.deploy → (你在游戏里资产导入+摆放)
```

成熟度标注遵循本仓库的诚实状态位纪律（[docs/30 §6](../docs/30_任务分解与模块化方法论.md)）：
"离线自测通过"指代码与机器验收完成但还没走完真实导入终审——**L2 全绿 ≠ L3 会过**，
这正是分级验收要防的自欺。

## 2. core —— 基础设施（被调用，不是业务模块）

**干什么（人话）**：所有模块共用的"变速箱"。你不会直接调它跑业务，但每次调用业务模块
时都是它在开车：计时、跑前置、跑执行、跑后验、落版本、写日志、数失败次数。

**它自动保证了什么**（每个业务调用免费附赠）：

1. **统一的调用流程**：前置检查 → 执行 → 后验 →（通过）写日志 + 落新版本 /
   （拒绝）不入账。**坏调用从构造上产生不了新版本**——版本指针没动，就是没动。
2. **三种失败三种处理**：

| 异常 | 含义 | 后果 |
|---|---|---|
| `PreconditionError` | 前置不过（输入形态/状态不满足） | 不执行、不计失败——"此路不通"，换路 |
| `ModuleRejected` | 后验不过（产物不合格） | 不入账（指针不动）+ 计一次连续拒绝 |
| `ConsecutiveRejectError` | 同一模块连续 4 次被拒 | 强制罢工信号——这条路走不通，换思路，别第 5 次重试 |

3. **版本落盘字节守恒**：每次成功落版后，基础设施自己复核"存档字节 == 产物字节"，
   不一致直接响亮报错（这是基础设施事故，不许静默）。
4. **全程留账**：每次调用（含失败的）都追加进 `state/oplog.jsonl`，含参数摘要、
   逐项验收结果、版本号、耗时。

**统一返回值 `core.Result`**（每个模块都返回它）：

| 字段 | 含义 |
|---|---|
| `ok` | 调用是否成功受理（`level.judge` 特殊：判决真值在 `value.passed`，见 §5） |
| `artifact` | 产物路径 |
| `checks` | 验收明细：`[(检查名, PASS/FAIL/TRIVIAL/…), …]`——逐项可审计 |
| `version` | 本调用产生的关卡新版本号（不落版的模块为 None） |
| `level` | 版本域名（版本存到 `levels/<域名>/` 下） |
| `value` | 查询型载荷（`log.query` 的条目、`entity.place` 的 guid 详情等） |
| `error` / `secs` | 失败原因 / 耗时秒 |

**常用辅助函数**（直接可用）：

```python
from mods import core

core.list_modules()                    # 所有已注册模块名（排序）
core.current_version("hello")          # 关卡 hello 当前版本号（无版本返回 0）
core.version_path("hello", 2)          # v2.gil 的路径
core.read_current("hello")             # 当前版本的字节（无版本 None）
core.rollback("hello", to_version=2)   # 指针回拨到 v2（不产新版本；目标版须存在且非当前）
core.reset_rejections()                # 清连续拒绝计数（换路后用）
```

**失败时你会看到什么**：直接调业务模块即可，异常会原样抛到你面前；
`ConsecutiveRejectError` 的消息形如 `level.mount 连续 4 次拒绝 → 编排器换路`。

## 3. graphgen.build —— 造一张节点图

**干什么（人话）**：你用大白话描述"几个方块、怎么连线、方块里写什么字"，它产出一张
格式合法的 `.gis` 图文件，并把它落成对应图域的第 1 版存档。
（依赖可选工具树 `QXY_TOOL_ROOT`——见 §0 第 2 条；未配置时前置拒绝并给指引。）

**函数签名**：

```python
from mods.graphgen import GraphLogic, Node, Exec

graphgen.build(logic: GraphLogic, name: str, guid: int) -> core.Result
# GraphLogic(nodes=[Node(id, kernel, text=None, note=None)], edges=[Exec(src, dst)])
#   Node.id    逻辑编号（本图内不重复即可，装配时自动重排）
#   Node.kernel 节点种类编号（558 种，见 docs/07）
#   Node.text   节点携带的字符串（如打印文本）；None 表示没有
#   Node.note   纯注释，不写入文件
#   Exec(src, dst) 执行边：src 完成后执行 dst
```

**最小调用示例**（真实可跑）：

```python
from mods import graphgen
from mods.graphgen import GraphLogic, Node, Exec

r = graphgen.build(
    logic=GraphLogic(
        nodes=[Node(1, kernel=71),                              # 「实体创建时」事件
               Node(2, kernel=1, text="[hello_loop] 圈活了")],  # 「打印」动作
        edges=[Exec(1, 2)]),
    name="hello",
    guid=0x40000001)        # 图 guid：必须在 0x4000 段（0x40000000..0x4000FFFF）
print(r.ok, r.version, r.artifact)
```

**它自动保证了什么**：

- **前置全查**：节点编号在游戏 558 种之列且可装配（不存在的方块装出来也会被编辑器
  删除）；图非空；编号不重复；连线两端都不悬空；打印文本 ≤ 1000 字符；图名非空、
  ≤ 64 字符、无路径分隔符；guid 是 int 且在 0x4000 图段。
- **后验四连**：产物连闯四道机器关卡——往返复现（roundtrip）、结构规则（verify）、
  形态门（form_gate）、基准对照（oracle_gate），全绿才交付。
- **确定性装配**：同参数重复调用，产出逐字节相同。
- 成功后图文件同时落成 `levels/<图名>/v1.gil` 存档（core 统一行为）。

**失败时你会看到什么**：

- 前置问题（`PreconditionError`，改输入再来）：
  `node 2 kernel 99999 不在 kernel 宇宙——不存在的节点装出来也会被编辑器删除`；
  `guid 0x40800001 不在 0x4000 段（0x40000000..0x4000FFFF，地图级图波段）`；
  `exec 边悬空: dst 3 不在节点集 [1, 2]`。
- 后验问题（`ModuleRejected`，连续 4 次会触发换路信号）：
  `后验门禁 form_gate 未过 (exit=1): …`（消息尾带关卡输出，直接定位病灶）。

## 4. level.mount —— 把图挂进关卡

**干什么（人话）**：图在抽屉里不会响。本模块把一张已过验收的 `.gis` 图装到关卡宿主上，
一次做完四件事：图进图库、挂到宿主实体、注册进资源树、实体名册登记——产出关卡新版本。
装配以你本机游戏目录里的关卡样本为底座与金样本对照（§0 第 3 条），零工具树可跑。

**函数签名**：

```python
level.mount(graph_gis: str, host_guid: int, graph_guid: int,
            category: int = 20000, level_name: str | None = None) -> core.Result
# graph_gis   .gis 图文件路径（graphgen.build 的 r.artifact）
# host_guid   宿主实体：唯一合法值 0x41400001（关卡宿主——每关固定一扇"大门"）
# graph_guid  图的 guid：模块会打开图头核对，与图内记录不符即拒
# category    挂载类别：服务器图 = 20000（默认）
# level_name  版本域名；缺省取 .gis 文件名主干（hello.gis → 域 hello）
# 成功：r.version = 关卡新版本号；r.value = 新版本 .gil 路径
```

**最小调用示例**：

```python
from mods import level

r1 = ...  # graphgen.build 的结果（见 §3）
r2 = level.mount(graph_gis=r1.artifact, host_guid=0x41400001,
                 graph_guid=0x40000001, category=20000)
print(r2.ok, r2.version, r2.value)
```

**它自动保证了什么**：

- **"图在库但没挂载 = 永远不执行"的坑在这里堵死**：四件事逐项闭合检查（V0–V7 八项），
  检查明细全部在 `r.checks` 里可逐条读。
- **防挂错**：打开图头，把你在参数里给的 guid、类别与图内权威记录二次核对——
  类别挂错宿主类型，图不报错、永远不触发（"永聋"），这一层必须在落盘前拦住。
- **装配先走临时槽**：产物先写在版本域之外的临时目录，验收全过才落成新版本——
  拒绝发生在落盘之前，坏调用天然不污染版本存档。

**失败时你会看到什么**：

- 前置（换路）：`graph_gis 不存在: …`；`host_guid 0x40460001 非 S0 唯一宿主 0x41400001`；
  `category 20001 不在 f501 四值挂载空间 [20000, 20003, 20005, 20007]`；
  `底座/金样本不可得（游戏目录未配置）`（附配置指引，见 §0）。
- 后验（不入账）：`graph_guid 0x40000002 与图头 guid 0x40000001 不符（图头=唯一权威源）`；
  `出口校验 2 项 FAIL: …`（FAIL 明细原文附上）。

## 5. level.deploy / level.judge —— 交付与判决

（两个模块同住在 `mods/deploy.py`，配套使用。）

### level.deploy —— 部署关卡到游戏导入目录

**干什么（人话）**：把关卡某个版本的字节复制到游戏导入目录，起个你在游戏里认得的
名字。纯搬运，搬完核对字节。

**函数签名**：

```python
level.deploy(level_gil: str, r_name: str, export_dir: str | None = None) -> core.Result
# level_gil  关卡版本 .gil 路径（如 level.mount 的 r2.value）
# r_name     游戏内显示名（单段合法文件名，如 "hello_loop_map_r1"；.gil 后缀自动补）
# export_dir 落点覆盖（自测零污染用）；缺省走 QXY_GAME_EXPORT，再缺省走自动探测（§0）
# 重复部署 = 覆盖（改版后重部署是常规流程）
```

**最小调用示例**：

```python
from mods import deploy

r3 = deploy.level_deploy(level_gil=r2.value, r_name="hello_loop_map_r1")
print(r3.artifact)   # …/Beyond_Local_Export/hello_loop_map_r1.gil
```

**它自动保证了什么**：落点存在且与源**逐字节一致**；不一致就删掉残件并拒收——
导入目录里的坏文件会被真人导入，残件绝不留盘。

**失败时你会看到什么**：`源 .gil 不存在`、`r_name 须为单段合法文件名`（前置）；
`源 .gil 为空（0 字节），拒绝部署`、`落点字节不一致（已尝试清除）`（后验拒收）。

### level.judge —— 等你试玩，机器判决

**干什么（人话）**：一个蹲守判决器。它先启动、进入等待；你去游戏里**导入 + 试玩**
（只有人能做的动作）；它守着磁盘，等新地图出现、等试玩日志写出，然后在新日志的
字节流里找你指定的那句打印文本。找到 = 通过，附上证据原文。

**函数签名**：

```python
level.judge(expect_print: str, timeout_min: float = 10.0, known_maps=None,
            mirror_dir=None, debug_dir=None, poll_sec: float = 4.0,
            level_name: str | None = None, graph_name: str = "hello",
            graph_guid: int = 0x40000001, host_guid: int = 0x41400001) -> core.Result
# expect_print  判决判据（必须与图里打印的文字一字不差）；空判据拒绝
# timeout_min   三相总预算（分钟）
# known_maps    相 1 基线（已导入地图集合）；None = 启动时刻快照
# 返回：r.ok = 观察是否完整跑完（恒 True）；r.value = Verdict 判决对象
```

**最小调用示例**（注意顺序：**先启动判决，再去游戏里导入试玩**）：

```python
from mods import deploy

v = deploy.level_judge(expect_print="[hello_loop] 圈活了", timeout_min=10)
print(v.value.passed)    # True = 判决通过
print(v.value.evidence)  # 命中证据：打印字节前后的可读上下文
print(v.value.map_id)    # 观察到的新地图 id
```

**它自动保证了什么**：

- **判决只认磁盘证据**：`value.passed == True` 当且仅当 expect_print 的字节确实出现在
  新写的试玩日志（`.gia`）里——不推理、不脑补、不"应该没问题"。
- **三相如实报告**：判决对象 `Verdict` 的 `reason` 字段告诉你卡在哪一相——
  `timeout_no_new_map`（没等到你导入）/ `timeout_no_new_debug_log`（日志门没开或没试玩）/
  `print_not_found`（试玩了，但没打出那句话）。结构解剖明细进 `evidence`/`struct`，
  只作诊断证据，绝不反向冒充判决。
- **注意语义**：`r.ok` 表示"观察器完整跑完"（超时也算跑完）——**判决真值永远读
  `r.value.passed`**。

**失败时你会看到什么**：`expect_print 为空——拒绝空判据（不冒充）`（前置）；
判决不通过时 `passed=False` + 上述三种 reason 之一 + 观察到的证据文件路径。
另注意：导入必须发生在判决启动**之后**（先导入会被当成旧地图，白等到超时）。

## 6. terrain.patch —— 地形定点手术

**干什么（人话）**：对关卡现有地形做"只动目标格"的微手术：改层位、加坡、换材质、
注水、铺路径。一格一条指令，改完逐格复查，保证没溅射到任何邻居格。

**函数签名**：

```python
terrain.patch(level_name: str, cells: list) -> core.Result
# cells 每格一令：{"gx": int, "gz": int, 字段: 值, ...}
#   gx/gz        格坐标，范围 100..119（20×20 设计网格）
#   字段（白名单）: layer(层位 1..3) / slope(坡) / material(材质 1..8) /
#                  water(0/1) / path(0/1)
# 成功：r.version = 关卡新版本号；r.value = 新版本 .gil 路径
```

**最小调用示例**：

```python
from mods import terrain

r = terrain.patch(level_name="hello",
                  cells=[{"gx": 107, "gz": 106, "layer": 1},
                         {"gx": 109, "gz": 103, "water": 1}])
print(r.ok, r.version)
```

**它自动保证了什么**：

- **前置六检**：格键范围、坡互斥律（同格不得坡与水/路径并存——既查本批、也查底座
  现状）、层位值域、字段白名单（拼错字段名直接拒，绝不静默丢操作）、值域、
  底座在位且目标格已存在。
- **后验六项**（对产出文件独立重读，不信内存账）：往返复现；**块数对账**（操作后
  总块数 == 操作前 + 新增数——"只写变化块、其余全丢成虚空"这类事故靠它拦，
  逐格抽查是抓不住的）；组结构对账；格键集合守恒；变更格逐字段读回；**无辜格守恒**
  （全部未触碰格的五字段快照逐格相等——手术不许溅射邻居）。
- 成功即落关卡新版本，天然可回滚。

**失败时你会看到什么**：

- 前置（换路）：`cells[0] gx=99 越界（格键范围 100~119）`；
  `格 (109,103) 底座已有坡(f6=16)，不得设water（互斥律）`；
  `目标格不在底座 group0（空格=虚空，不支持造块）: (115,115)`。
- 后验（不入账）：`后验 1 项 FAIL: tile_count_reconcile(412==400+0)`。
- 约束须知：底座关卡必须已有地形组（无地形的图先补地形底座）；不支持造块/删块；
  只手术第一地形组。

## 7. entity.place —— 放置官方实体

**干什么（人话）**：从官方模板库（约 2473 件 prefab）里拿一件，盖到你给的坐标上。
自动处理全部登记手续（名册 + 分组树双注册），自动分配或校验身份证号。
（依赖可选工具树 `QXY_TOOL_ROOT`——见 §0 第 2 条。）

**函数签名**：

```python
entity.place(aid: int, pos, level_name: str = "hello",
             guid: int | None = None, yaw: float = 0.0, scale=None) -> core.Result
# aid         官方资产 id（模板库里有才能放）
# pos         位置：(x, z) / (x, z, y) / {"x":..,"z":..,"y":..}；y 缺省 = 贴地
# level_name  版本域名（须已有当前版本——先跑过 level.mount 或 level.checkpoint）
# guid        实例身份证号；None = 全档扫描自动分配（机关入 0x404 段、怪物入 0x408 段，
#             分配即记账防撞号）；显式给定时校验段位律与撞号
# yaw         Y 轴旋转【度】（单位是度，不是弧度；0 = 不写旋转）
# scale       (sx, sy, sz)；None = 模板缺省 1,1,1
# 成功：r.value = {"guid", "aid", "entity_count", "alloc", "band", ...}
```

**最小调用示例**：

```python
from mods import entity

r = entity.place(aid=20001018, pos=(5.0, 5.0))   # guid 自动分配
print(r.ok, r.version, r.value["guid"])
```

**它自动保证了什么**：

- **双注册自动完成**：放置即同时登记 f5 实体名册与 f6 分组树叶——怪物缺一不生效的
  硬律、机关与编辑器原生形态的一致性，都由它兜底（背景见
  [概念指南 §8](概念指南.md)）。
- **段位律强制**：怪物 aid 必须落 0x408 段、机关落 0x404 段（段放错，实体在游戏里
  不渲染）；自动分配的号避开编辑器惯用低区并记入台账防撞。
- **全档闭合后验**：产物读回后检查——实体数恰好 +1；新 guid 在全文件中**恰好出现
  2 处**（身份位 + 注册叶，多一处少一处都是悬空引用，拒收）；注册叶在位；
  实体形态门禁（trial_gate）通过。
- **底座原则**：以当前版本为底座只追加不重排，其余顶层字节原样保留。

**失败时你会看到什么**：

- 前置（换路）：`aid 12345 无 prefab 模板——先查正确资产 id 再调用`；
  `aid …（'某装饰'）placeable=False——不可放置资产，换 aid`；
  `guid 0x40800001 不在段 0x40400000-0x40500000（段位律：机关 aid … → 0x404 段，
  段错不渲染/渲染错类）`；`guid 0x40460001 与关卡现有内容撞号（全档 varint 扫描）`；
  `关卡 'hello' 无当前版本——先 level.checkpoint/level.mount 建版`。
- 后验（不入账）：`后验不过: ['entity_count_audit FAIL (5->7)']`、
  `trial_gate 拦截: [SICK] …`（病灶原文）。

## 8. state —— 手动存档、回滚、查账

（三个小件同住在 `mods/state.py`，都是关卡域的基础操作。）

### level.checkpoint —— 手动落一版

**干什么（人话）**：把一份 `.gil` 文件的字节落成指定关卡域的下一版——大操作前
手动存档、或者你在编辑器外人工操作后把结果收编进版本制，前后各夹一版。

```python
level.checkpoint(level_name: str, source_gil: str) -> core.Result
```

```python
from mods import state

r = state.level_checkpoint(level_name="hello", source_gil="手改后的关卡.gil")
print(r.version)   # 新版本号
```

**保证**：源文件存在且非空才收；落盘字节守恒由 core 自动复核。
**失败**：`源 .gil 不存在`（前置）；`源 .gil 为空（0 字节），拒绝落版`（拒收）。

### level.rollback —— 版本指针回拨

**干什么（人话）**：把"当前版"指针拨回某个历史版本。不产生新版本、不删任何存档——
拨错了还能再拨回来，因为所有版本都在。

```python
level.rollback(level_name: str, to_version: int) -> core.Result
```

```python
from mods import state

r = state.level_rollback(level_name="hello", to_version=2)
```

**保证**：目标版必须存在且不是当前版（否则前置拒绝）。
**失败**：`hello v9 不存在，无法回滚`、`hello 已在 v2，无需回滚`。

### log.query —— 查操作日志

**干什么（人话）**：查账。谁在何时调了什么模块、参数是什么、验收结论如何、落了
哪一版——全在这。排查"这份文件是谁写的"、盘点"哪些活已经干完"都靠它。

```python
log.query(module: str | None = None, seq_from: int | None = None,
          seq_to: int | None = None, ok: bool | None = None) -> core.Result
# 四个过滤条件可任意组合；条目列表在 r.value
```

```python
from mods import state

r = state.log_query(module="level.mount", ok=True)
for row in r.value:
    print(row["seq"], row["ts"], row["version"])
```

**保证**：纯读模块——查询本身不写日志、不碰版本。
**失败**：基本不会失败；没命中就返回空列表。

## 9. asset —— 资产包通道

（两个模块同住在 `mods/asset.py`，走"资产导入"而不是"关卡导入"。）

### asset.package —— 把实体打包成资产包

**干什么（人话）**：把一个或多个"官方模板 + 位置"描述打包成一个 `.gia` 资产包，
让你在游戏的资产导入界面把它当一件"自制品"导入使用。
（依赖可选工具树 `QXY_TOOL_ROOT`——见 §0 第 2 条。）

```python
asset.package(items, name: str, map_id: str = "1073742009",
              out_dir: str | None = None) -> core.Result
# items  最小形态 {"aid": 官方资产id, "pos": (x, z)}；单件 dict 或其列表；
#        可选 guid（缺省自动分配记账）。多元件/染色/碰撞等复杂形态在扩展计划中
# name   包名（单段合法文件名，可含中文；.gia 后缀自动补）
# out_dir 落盘目录覆盖；缺省 = 状态根 state/assets/
# 成功：r.artifact = .gia 路径；r.value = {"path", "count", "guids", "gate"}
# 注意：资产包不落版本存档（版本槽形制是关卡 .gil 专用）
```

```python
from mods import asset

r = asset.package(items={"aid": 20001018, "pos": (0.0, 0.0)}, name="我的长凳")
print(r.ok, r.artifact)
```

**它自动保证了什么**：合成与包装内建往返验证；出厂前过**实体形态门禁**
（trial_gate——染色正典、号段、形态合规的机器体检），体检不过不出厂；
自动分配的 guid 记账防撞。

**失败时你会看到什么**：`items[0].aid 12345 无 prefab 模板（official_prefab_db）——先查
正确资产 id 再调用`（前置）；`trial_gate 拦截: [SICK] …`（后验，病灶原文附上）。

### asset.deploy —— 资产包部署到导入目录

**干什么（人话）**：把打包好的 `.gia` 复制进游戏导入目录（与 level.deploy 同一套
纪律：字节一致、残件不留盘、重复部署即覆盖）。

```python
asset.deploy(gia_path: str, export_dir: str | None = None) -> core.Result
```

```python
from mods import asset

r2 = asset.deploy(gia_path=r.artifact)   # r 是 asset.package 的结果
print(r2.artifact)   # …/Beyond_Local_Export/我的长凳.gia
```

**保证与失败**：同 `level.deploy`（§5）；额外一条领地规则——只收 `.gia` 后缀
（关卡走关卡链，资产走资产链，不串门）：`非 .gia 资产包（领地: .gia 通道）`。

## 10. 把链路跑起来（最小完整流程）

```python
from mods import graphgen, level, deploy
from mods.graphgen import GraphLogic, Node, Exec

# ① 造图（图域第 1 版）
r1 = graphgen.build(logic=GraphLogic(
        nodes=[Node(1, kernel=71),
               Node(2, kernel=1, text="[hello_loop] 圈活了")],
        edges=[Exec(1, 2)]),
    name="hello", guid=0x40000001)

# ② 挂载进关卡（关卡 hello 第 1 版）
r2 = level.mount(graph_gis=r1.artifact, host_guid=0x41400001,
                 graph_guid=0x40000001, category=20000)

# ③ 部署到导入目录
r3 = deploy.level_deploy(level_gil=r2.value, r_name="hello_loop_map_r1")

# ④ 先启动判决 → 你去游戏里导入并试玩 → 读判决
v = deploy.level_judge(expect_print="[hello_loop] 圈活了", timeout_min=10)
print("判定:", v.value.passed, "| 证据:", v.value.evidence)

# ⑤ 想继续叠加内容？在当前版本上接着调（entity.place / terrain.patch），
#    每次成功自动 +1 版；搞砸了 level.rollback 拨回去。
```

每一步的 `checks` 都值得打印出来读——那是这台机器的验收底账，
也是本仓库最提倡的习惯：**相信证据，不信感觉**。

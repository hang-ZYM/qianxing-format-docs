# 概念指南 · 用大白话读懂千星奇域创作

> 写给**会一点 Python、但完全没碰过游戏逆向**的读者。
> 本仓库的手册层（manuals/）和卷宗层（docs/）是为 AI 读者优化的作业资料，名词密度高；
> 这一篇是对症的人话导览：十个核心概念，每个都按
> **一句话定义 + 生活类比 + 在本仓库里怎么用** 三段讲清。
> 读完这一篇再去看[模块参考](模块参考.md)就能动手；想深挖原理，每节末尾给了对应卷宗。

## 开始之前：三个文件后缀 + 两个词

千星奇域（原神的 UGC 玩法）的关卡不是文本文件，是**二进制文件**。你只会遇到三种后缀：

| 后缀 | 是什么 | 生活类比 |
|---|---|---|
| `.gil` | **关卡文件**——一张地图的全部家当：实体、地形、节点图、各种注册表，全装在里面 | 行李箱 |
| `.gis` | **图文件**——一张节点图，还没装进关卡行李箱的散件 | 一件还没塞进箱子的衣服 |
| `.gia` | **包裹文件**——同一个后缀两种用途：①"资产包"，把做好的实体打包带走；②"试玩日志"，游戏试玩时自动写下的运行记录 | 快递盒：既能装货，也能装行车记录仪 |

两个会反复出现的词：

- **guid**：每个对象的**全局唯一编号**，一个大整数，习惯写成十六进制（如 `0x40460001`）。
  相当于身份证号——引用谁、挂载谁，全靠号码对号码。
- **kernel（节点种类编号）**：游戏内置 558 种节点（见 [docs/07 节点大全](../docs/07_节点大全.md)），
  每种一个编号。比如 kernel 71 =「实体创建时」事件节点，kernel 1 =「打印字符串」节点。

## 1. 元件（0x40C）—— 盖章的章

**一句话**：元件是游戏版的 Prefab（预制件，游戏开发行话：预先做好的物件模板）——
你把一组做好的东西存成一个"章"，之后随时到处盖。

**类比**：橡皮章。刻一次，盖一百次；章本身不是画，盖出来的印才是画。
游戏里的「默认模板」章固定是 `0x40C00001` 这个号；你自己刻的章从 `0x40C00002` 往后排。

**在本仓库怎么用**：
- 章有章的编号段（0x40C），盖出来的印有印的编号段（0x404，见第 4 节"号域"）——
  「创建元件」节点引用的是 0x40C 的**模板号**，真正落到场景里的是 0x404 的**实体号**。
  这套"模板层 ↔ 场景层"两套号并行的规则叫**元件双号制**，
  定案见 [docs/10 §4.4](../docs/10_其他内容域.md)。
- 往场景里"盖一个现成官方模型"这件事，在模块库里是 `entity.place`（给一个官方资产 id + 位置）。

## 2. 实体 —— 用章盖出来的实例

**一句话**：实体是场景里的一个具体对象（一只怪、一个机关、一块木板），相当于游戏引擎里的
GameObject（场景物体——游戏开发行话：世界里每一个"东西"都是一个对象）。

**类比**：章盖出来的每一个印。同一枚章（元件模板）盖出来的两个印是两个独立实体——
改其中一个的位置，另一个不动。

**在本仓库怎么用**：
- 实体登记在关卡文件的两个地方：**f5 字段**是实体总名册（谁存在于场景里），
  **f6 字段**是分组树（谁属于哪个页签，比如编辑器实体面板的"未分类页签"）。
  字段编号 f5/f6 的说法贯穿全部卷宗，源头是关卡文件的二进制结构
  （见 [docs/03 数据模型总表](../docs/03_数据模型总表.md)）。
- 模块库里 `entity.place(aid, pos)` 就是"拿官方章、盖在你给的坐标上"，
  它自动处理名册登记（见第 8 节"双注册"）。
- 官方实体编目在 [docs/08 实体大全](../docs/08_实体大全.md)（2466 种）；
  其中可放置的官方模板（约 2473 件 prefab）就是 `entity.place` 盖章用的"章库"。

## 3. 组件（cid）—— 对象身上的功能零件

**一句话**：组件是挂在实体身上的功能零件（位置、交互、受击特效……），cid 是零件的型号编号。

**类比**：Unity 的 Component，或者乐高的功能块——同一个底盘（实体），装上"交互块"就是机关，
装上"受击特效块"挨打就会冒光。一个实体身上装一排零件，各管一摊。

**在本仓库怎么用**：
- 组件有一条铁律：**实体第 cid 号零件的配置数据，放在"cid + 10"号字段里**。
  比如 1 号零件（位置/变换，几乎所有实体都有）的配置在 11 号字段——坐标、旋转、缩放都在里面。
  全部零件的型号与配置格式编典在 [docs/12 组件全典](../docs/12_组件全典.md)。
- 平时你不需要手拼零件：`entity.place` 合成实体时，官方模板自带的"底盘零件"
  （位置/命名/受击特效等）会原样带上，你只填位置、旋转角、缩放这几个参数。

## 4. 号域（0x4000 / 0x404 / 0x408 / 0x40C）—— 不同类身份证的号段

**一句话**：guid 不是随便取的——它的高 16 位是**类型域**，不同种类的对象用不同的号段。

**类比**：身份证号段或电话区号：一看开头就知道这个人/这通电话来自哪类。
千星奇域里，看一个 guid 的开头就知道它是哪类对象：

| 号段 | 装哪类对象 | 记法 |
|---|---|---|
| `0x4000` | 节点图（每张图一个号） | 00 开头最"轻"——图是逻辑，不是实体 |
| `0x404` | 机关/造物实体（元件盖出来的印也在这段） | 04：机器在前 |
| `0x408` | 怪物实体 | 08：活物在后，"怪"与 8 谐音 |
| `0x40C` | 元件模板（章柜） | 0C：C = Component，模板收藏柜 |

**在本仓库怎么用**：
- **段放错，对象就不显示**——怪物号落进机关段，进了游戏它就是空气。这条"段位律"是
  模块库的硬前置：`entity.place` 会按资产类型自动校验/分配正确号段，`graphgen.build`
  强制图 guid 必须在 0x4000 段。你手写 guid 时撞号也会被拦（全档扫描后拒绝）。
- 完整段位总表（20 多个段，含技能/道具/商店等资产段）见
  [docs/10 §4](../docs/10_其他内容域.md)。0x4000 段有个特别规则：它是多命名空间池，
  图、UI 模板、存档模板各自独立计数，**同一个数字在不同域里可以并存**，所以禁止跨域查重。

## 5. 节点图 —— 游戏里的"编程"

**一句话**：节点图是可视化脚本——把"事件 → 动作"用方块和连线摆出来，不用写代码。

**类比**：Scratch 积木，或者工厂的流程图：一个方块是"收到订单"（事件），下一个方块是
"打包发货"（动作），中间画个箭头表示先后。千星奇域内置 558 种方块（kernel）。

**在本仓库怎么用**：
- 一张最小可跑的图只要两块一线：**「实体创建时」（kernel 71）→「打印」（kernel 1）**。
  模块库的 `graphgen.build` 吃的就是这种"方块+连线+文字"的描述，产出一个 `.gis` 图文件。
- 方块不是随便拼的：不存在的编号装出来也会被编辑器删掉，所以造图前会先过
  "编号是否在游戏 558 种之内"的前置检查。
- 图分两种执行环境（服务器图/客户端图，见第 7 节）；图造好后必须挂载（第 6 节）才会跑。

## 6. 挂载 —— 把脚本装到对象上

**一句话**：挂载是把一张图"装"到某个实体身上，图才会被执行——就像门铃装到门上才会响。

**类比**：门铃。图是门铃的电路板，实体是门。电路板放在抽屉里（图库里）永远不会响；
必须装到门上、接好线，有人按（事件发生）它才响。

**在本仓库怎么用**：
- 最常见的挂法：挂到**关卡宿主**上。每张关卡有一个唯一的"关卡实体"（guid 固定
  `0x41400001`），它就是那扇"大门"——图挂到它身上，进图即触发。
- 这一步在模块库里是 `level.mount`。它是全链路最容易翻车的坑位，因为"图已经造好、
  已经进了关卡文件"和"图真的会执行"是两回事——**图在库但没挂载 = 永远不执行**，
  而且不报任何错。`level.mount` 一次做完四件事（图入库、挂到宿主、注册进资源树、
  实体名册登记）并逐项闭合检查，就是专门堵这个坑的。

## 7. 服务器图 / 客户端图 —— 后端逻辑 vs 前端表现

**一句话**：同一套"方块+连线"的写法，跑在两个地方——服务器图在服务器上跑（权威判定），
客户端图在每个玩家的设备上跑（表现与 AI）。

**类比**：网页应用的前后端。转账扣款必须跑在后端（谁都不能作弊）；按钮变色、动画特效
跑在前端（每个用户看到自己的那一份）。怪物"发现玩家→追击→放技能"的脑子（AI）
也是客户端图——每个玩家设备上各自演算自己看到的那只怪。

**在本仓库怎么用**：
- 图有个"类别"属性决定它跑在哪边。挂载服务器图用类别号 20000（`level.mount` 的默认值）；
  客户端图族（怪物 AI 的决策图/状态图/技能图三类）见
  [docs/25 客户端图与自定义 AI](../docs/25_客户端图与自定义AI.md)——那是从零造一只有
  自定义 AI 的怪的正典卷。
- 两边的连线方言一致，造图工具通用；但类别空间是两套，挂错了宿主类型图会"永聋"
  （不报错、永远不触发），所以 `level.mount` 会拿图头记录的类别做二次核对。

## 8. 双注册 —— 花名册要登记两次才生效

**一句话**：一个实体（尤其怪物）必须在关卡文件的两个地方各登记一次才真正存在——
只在名册里、不在分组树里，游戏不认。

**类比**：新生入学要同时进两个名单：**学籍名册**（这个人存在）和**班级座位表**
（这个人归哪个班管）。只交学籍没排座位，点名永远点不到你。

**在本仓库怎么用**：
- 两处登记对应关卡文件的两个字段：**f5 = 实体总名册**，**f6 = 分组树**。
  本项目对全部 33 个本地关卡样本做过逐字节对账：怪物的双注册是硬律
  （132 个怪物样本 120 个双注册，12 个例外走的是另一套系统注册面，无一漏网）；
  机关虽非强制，但双注册是编辑器自己保存时的原生形态。
- 你不需要手工登记：`entity.place` 放置任何实体都会自动完成双注册，并在后验里检查
  "新 guid 在全文件中恰好出现 2 处（名册 1 次 + 树叶 1 次）"——多一处少一处都算残次品拒收。

## 9. 操作日志 / 版本 —— 游戏存档槽 + 改动历史

**一句话**：模块库每通过一次验收就把关卡落成一个新版本（v1、v2、v3……），同时把
"谁、何时、做了什么、验收结果、版本号"追加进一份只增不删的日志；回滚 = 把"当前版"指针拨回去。

**类比**：游戏存档槽 + 成就时间线。每次打赢一个关卡节点自动存档；哪次操作搞砸了，
读回上一个存档就行，而且时间线永远记得你每一步干了什么。

**在本仓库怎么用**：
- 磁盘形态：`levels/<关卡名>/v1.gil、v2.gil……` 加一个 `current.json` 指针（指向当前版）；
  日志是 `state/oplog.jsonl`，一行一条、只追加。
- 核心思想一句话：**已验证的操作日志是权威状态，产物只是日志的投影**
  （[docs/30 §2](../docs/30_任务分解与模块化方法论.md)）。产物会被游戏改写、会损坏；
  日志不会。怀疑"现在这份关卡对不对"，永远去查日志，而不是肉眼盯文件。
- 由此白得三个性质：**坏调用从构造上产生不了新版本**（验收不过 = 指针不动）；
  **失败最多损失一步**（拨回上一版）；**每个版本可审计**（这一版的字节是哪几次调用写的，
  日志里有账）。查询日志用 `log.query`，回滚用 `level.rollback`。

## 10. 验收分级 L1–L5 —— 从"语法检查"到"真机试玩"的考试难度

**一句话**：一个产物"对不对"分五级验收，从机器查字节到人试玩，一级比一级接近真相。

**类比**：驾照考试的阶梯：笔试（L1）→ 交规（L2）→ 体检报名（L3）→ 场地实操（L4）→
真路上路（L5）。笔试满分不代表能上路——所以每一级都要考，且**能考高一级就别停在低级**。

| 级 | 考什么 | 类比 | 本仓库对应 |
|---|---|---|---|
| L1 | 字节级：写出的文件能被自己的解析器原样读回 | 检查错别字 | `qxfmt roundtrip` |
| L2 | 结构级：满足已积累的全部格式规则 | 语法规则考试 | `qxfmt verify` |
| L3 | 装载级：游戏装载接受、内容逐个存活 | 报名资格审核 | 导入观察 + 重保存对比 |
| L4 | 运行级：跑起来的行为符合预期 | 场地实操 | 运行语义观察（[docs/23](../docs/23_运行语义实证.md)） |
| L5 | 人审：真机试玩，看着对、玩着对 | 真路上路 | **你**——人是唯一终审 |

**在本仓库怎么用**：每个模块的后验取它**可达的最高级**（能判 L2 的不会只判 L1）；
同时诚实声明自己判不了什么——L2 全绿不等于 L3 会过，这种"考不了试"的边界也测绘在档
（[docs/28 §1.2](../docs/28_验证方法与发现.md)）。分级表与整套方法论见
[docs/30](../docs/30_任务分解与模块化方法论.md)。

## 一次创作的完整旅程

把十个概念串起来走一遍。目标（**意图**）：

> "我要一张图：玩家一进来，屏幕上打印 `[hello_loop] 圈活了`。"

**第 1 步 · 分解**。这个意图拆成四步子任务：造图 → 挂载 → 部署 → 试玩判决。
每一小步都是一个模块调用，每步有自己的验收，不搞"一口气生成整张关卡"。

**第 2 步 · 调用模块造图**（对应概念：节点图、号域、L1/L2 验收）：

```python
from mods import graphgen
from mods.graphgen import GraphLogic, Node, Exec

r1 = graphgen.build(
    logic=GraphLogic(
        nodes=[
            Node(1, kernel=71),                                # 「实体创建时」事件
            Node(2, kernel=1, text="[hello_loop] 圈活了"),     # 「打印」动作
        ],
        edges=[Exec(1, 2)]),                                   # 1 → 2 执行边
    name="hello",          # 图名
    guid=0x40000001)       # 图的身份证号：必须在 0x4000 图段
print(r1.ok, r1.version, r1.artifact)
# True 1 runs/hello.gis   ← 图文件在 runs/；关卡 hello 的第 1 版已同步落档（v1.gil）
```

你交给它的是人话描述（两块一线一段文字）；它还给你的是**验过货的产物**：
编号合法性、连线不悬空、文本长度限额在造之前全查过；造完还要连闯四道格式关卡
（往返复现、结构规则、形态门、基准对照），任何一道不过，这个调用就**当作没发生**。

**第 3 步 · 挂载进关卡**（对应概念：挂载、双注册、版本）：

```python
from mods import level

r2 = level.mount(graph_gis=r1.artifact,   # 第 2 步产出的图文件
                 host_guid=0x41400001,    # 挂到唯一的"关卡宿主"这扇大门上
                 graph_guid=0x40000001,   # 必须与图头记录一致（防挂错）
                 category=20000)          # 服务器图
print(r2.version)   # 关卡新版本号：v2
```

从此不再是"一张散图"，而是"关卡的第 2 版"。图入库、挂到宿主、资源树注册、
名册登记四件事一次做完、逐项验收。

**第 4 步 · 部署到游戏导入目录**：

```python
from mods import deploy

r3 = deploy.level_deploy(level_gil=r2.value,        # 当前版本 .gil 的路径
                         r_name="hello_loop_map_r1")  # 游戏里看到的名字
print(r3.artifact)   # 落点：.../Beyond_Local_Export/hello_loop_map_r1.gil
```

纯搬运：字节一致地复制到游戏能看见的文件夹，搬完还核对一遍字节。

**第 5 步 · 你来试玩，机器判决**（对应概念：验收分级 L5、操作日志）：
导入和试玩是**只有人能做的动作**（白名单动作，模块不代劳）。判决模块的工作方式是
"我先蹲守，你去玩"——所以**先启动判决，再去游戏里导入试玩**：

```python
v = deploy.level_judge(expect_print="[hello_loop] 圈活了", timeout_min=10)
print(v.ok)             # 观察器是否完整跑完
print(v.value.passed)   # True = 判决通过
print(v.value.evidence) # 命中证据：打印字节的上下文窗口
```

它会等三件事：等你导入（新地图出现）→ 等试玩日志（新的 `.gia`）→
在日志字节里找那句打印。**passed=True 当且仅当那串字节真的出现了**——
找不到就如实告诉你卡在哪一步（没导入/没开日志门/没找到打印），绝不编造"应该没问题"。

**如果中途失败会怎样**——三种失败，三种损失，全部自动处理：

| 失败点 | 发生什么 | 你损失了什么 |
|---|---|---|
| 前置检查不过 | 直接不执行，告诉你原因 | 零（连文件都没碰） |
| 后验不过 | 拒收，版本指针不动 | 零版本变化（重试即可） |
| 试玩判决不过 | 产物保留（它没坏，是行为不对），判决和证据回流给你 | 触发一轮修复，而非从头再来 |

这就是整套体系的承诺：**任何一步失败，你最多退一步，永远不会站在一堆来路不明的文件前
发呆。**想跑通这条旅程，翻[模块参考](模块参考.md)；想理解"为什么必须这样设计"，
读 [docs/30 任务分解与模块化方法论](../docs/30_任务分解与模块化方法论.md)。

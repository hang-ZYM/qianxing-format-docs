## 2. ClientTypeId（客户端表现类型）[P]

后期独立设计，编号规整（**List = Base + 1**）：

1/2=Entity/List, 3/4=Int, 5/6=Bool, 7/8=Float, 9/10=String, 11/12=Vector, 13/17=Enum, 14/15=Guid, 16=Faction, 18-20=Config/Prefab族。

类型定义消息（TypeDefinition）用 `f1: backend(1=Server, 2=Client)` 区分两套体系，ServerType 再带 `impl(0=primitive/1=struct/2=pair)` 与结构体/字典绑定（f100/f101）[P]。

## 3. 类型代数（节点目录侧）[C]

上游 558 节点目录（data.json）用一套字符串类型代数：

```
基本型: Int Flt Bol Str Vec Gid Ety Pfb Fct Cfg Vss Loc
容器:   L<X> 列表   D<K,V> 字典   S<...> 结构体   E<四字码> 枚举

```

使用统计：数据引脚 2314 个中 Entity 370 / Int 332 / Float 303 / **R<T> 214** / Bool 190 / Vector 184。

## 4. 泛型节点实例化（五件套）[J]

80 个泛型节点共 3252 个实例化重载（Variants），每个 Variant 声明 `{Constraints:"C<T:Int>", KernelID, InjectedContents:[{pin, TypeSelectorIndex}]}`。把一个泛型节点实例化为具体类型，需同时改五处：

1. `kernel_ref.runtime_id` ← Variants[i].KernelID（shell_ref 不动）
2. R<T> 引脚的 f4 类型码 ← T 的 ServerTypeId
3. 引脚 TypedValue 内 type_def 的 tag 同步替换
4. val_poly.chosen_type_index ← TypeSelectorIndex（默认 0 省略）
5. 值 storage 字段按 T 转换（int→float 时 f102→f104，且必须是包裹消息）

**值随型走**：带值引脚换型时只改 1-4 不改 5，编辑器保存时会把值丢掉（规范化）[J]。

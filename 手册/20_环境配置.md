## 4. 关键帧组与「随时间自动切换」

### 4.1 组与关键帧的结构

```
组      = { f1: 生效位(bool，可省), f2: 基准值(可省), repeated f3: 关键帧 }
关键帧   = { f1: 该刻值(float 或 ARGB uint), f2: { f1: 小时(0–23), f2: 分钟(0–59) } }
```

- **小时 = 0 与 分钟 = 0 均省略**（0:00 ⇒ 空时间子消息）。（[A]，三路真实字节逐字段一致）
- 旧注「`f3 = {ARGB, {通道编号, 参数}}`、`f2.f1` 值 4–13 是渐变通道」**已证伪**：f2.f1 全档取值最大 23、f2.f2 最大 59，是**小时 : 分钟**。

### 4.2 关键帧与 cfg 顶层 `f1` 无关（反证）

- cfg 顶层 repeated `f1`（8 条）与关键帧**不同增减**：存在某档 `f1` = **0 条**、而 f24/f26/f30… 各含 **8 条** f3 关键帧（[A]）。
- 故 `f1` **不是**「时段 / 关键帧槽位」（旧注已废）——它是**生效目标 / 选择玩家**（§3 f1）。
- 「时间点 / 关键帧」在**每个参数组自己的 f3** 里。

### 4.3 静态渲染读哪个值

- 一条曲线在「静态档」与「随时间档」之间**逐字节相同** → **静态渲染读组的 `f2` 基准值、不读关键帧**（[J]：官方「黑色」与「白天」两个具名预设关键帧逐字段相同，仅 `f2` 不同，观感迥异）。

### 4.4 「随时间自动切换」的落点（三件套）

1. **cfg 顶层 `f3=1`** = 总开关；
2. **每个参数组内多出 `f1=1`** = 该参数的时间曲线生效；
3. 组内 repeated `f3` 时点表 = 曲线本体。

> 旧注「自动切换 = 某字段内的 f3 关键帧序列」**不完整**（漏了 cfg 顶层 f3=1 与组内 f1=1 两件）。（[A]，真字节对齐）

- **待核**：`f3=1` 时引擎到底按关卡初始时间点采样时点表，还是仍读 `f2` —— **采样机制未验**（有对照件待目视）。cfg `f58` 是否参与亦**未证**。

## 7. 天气 / 雾（`f75.f1.f3`）

### 7.1 结构

```
f75.f1.f3 （天气列表）
 ├ f1   uint          （顶部开关，常见 =1）
 ├ f2   repeated 天气条目
 │    └ 条目 = { f1:uint(初始生效), f2:str(天气名，如"天气1"),
 │               f3:enum(天气类型，当前仅雾), f4:bool, f51:雾参数群 }

```

- **无雾 = 3B 占位 `{f501:1}`**；有雾 = 含 `{f1,f2}` 条目 + `f51` 参数群（[A]）。

### 7.3 定案 / 未定

- **`f17` = 远雾点距离(m) = 视野限制器**：官方具名预设「望远」= 3000 /「挡视线大雾」= 200、出厂 2400、用户实测 **40 生效**（[A][J]）。属**强关联**（语义单调），**非单变量证明**。
- **`f17` 无引擎下限**：反编译雾序列化类及其全部引用类**无 clamp / range / 校验代码**；**200 是编辑器滑块下限、不是引擎下限**（[R][J]）。
- **雾色 = `f51` 的 `f15` / `f16` / `f20` 的 base**（ARGB；**α 有效**，可做半透明雾）（[A]）。
- **雾「随时间自动切换」= `f51.f25`**（[A][J]：用户关闭后该字段消失，颜色关键帧仍保留）。
- **浓度 = `f18` 或 `f19`**：用户手改实证**两个都动过**，**到底哪一个未定**；`f21` 已由同一实证排除（[A][H]）。
  > 注：`docs/04_对齐.md` §2.C 的「浓度字段」行仍把 `f21` 列为候选（该行标注「未知」，系更新前口径）——以本卷为准，待 docs/04 同步。
- **距离雾 / 高度雾逐项对号 = 推断**：只有 `f17` 强实证；`f2` / `f8` 两个开关、`f13` 雾气高度、`f22` 近雾点距、`f4`/`f5`/`f7`/`f10`/`f14` 标量族**全是推断**（[H]，无单变量样本）。
- **雾色定案（项目口径）= 纯黑 `0xFF000000`**（黑天空配黑雾；实测优于冷蓝灰）（[J]；**以用户眼睛为准**）。出厂灰蓝 `0xFF8394AA` 感知亮度约 57%，在黑天空下发白。

## 8. 时间

### 8.1 关卡级时间（`f11.f1`）

| 字段 | 语义 | 类型 | 默认 | 值域 | 证据 |
|---|---|---|---|---|---|
| `f11.f1.f17` | 关卡初始时间点（小时） | int | **10** | 0–24（整数，全档无 >24） | [A][D][R] |
| `f11.f1.f18` | 每秒流逝时间（分钟）= 流逝比例 | float | **24** | 0.01–60（**缺失 = 0**） | [A][D][R] |

- 界面「每秒流逝时间（分钟）」与 `f18` **数字一一对应、无需换算**（[J]）。
- **缺失 = 0**：proto 标量缺省即 0，且反编译只在值 ≠0 时写该 tag；编辑器把默认 24 显式落盘 →「缺 f18」只能是作者把流速设成了 0。（[A][R]）
- **字段号 ↔ UI 项缺直证**，属**强推断**（靠值域 + 默认 + UI 键存在三者合推）（[H]）。
- `f11.f1` 其余字段（`f1` 生效范围 vec3、`f14`/`f15`/`f20` 等）语义未定（[H]）——关卡设置字段表见 10 篇 §1。
- 相关节点：kernel **664 查询当前环境时间** / **665 设置当前环境时间** / **666 设置环境时间流逝速度**（见 07 篇）。其中 **666 的「提瓦特速度」三源冲突**（官方节点表 = 1 / 官方环境配置页 = 24 / 第三方 = 24）——**存疑**。
- **待核**：665 的 float 小时与曲线 `{小时, 分钟}` 是否联动 / 是否插值——**不能判**（官方文档只讲「会变」，不讲插值与取整方式）。

### 8.2 「时间」环境（第二种环境配置）

- 落点 = `f15` 又一条 `tc=26`，guid **`0x46C00002`**，名称「时间」（[A]）。
- **没有环境级流速字段**——推进速度仍由关卡级 `f11.f1.f18` 或节点决定（[A]）。
- 它的实质 = **自带时点表的「随时间自动切换」环境**：cfg 顶层 `f3=1` + 每组内 `f1=1` + 组内 `f3` 时点表。与出厂默认环境对拍，其**唯一实质差异 = 各组的时点表被大幅裁剪**（每组只剩 1–4 个时点）（[A]）。
- 与 `f11.f1.f17` / `f18` 是**配套关系**（f11 定起点 + 流速，环境定「各时点长什么样」），**非替代**（[A][D]）。
- **待核**：cfg `f58`（=10）是否参与、时点表裁剪规则（[H]）。

## 14. 环境光源资产与实体光照组

### 14.1 环境光源资产（`f15` `tc=27`，载荷 `f74`）

```
f74 = { f1: { f1: <光源组件> , f2: uint(=1) } }        ← 光组件被 {f1:光组件, f2:uint} 壳包着
光源组件 = { f1: 仅聚光灯携带（聚光灯标志位）, f2: f32(生效范围), f3: vec3(位置), f4: vec3(旋转), f5: uint(恒=1),
             oneof { f51: 参数组A, f52: 参数组B } }
```
- 外层 `f74.f1.f2` = uint(1)（未定）；`f74.f1.f1.f2` = 生效范围、`f3` = 位置、`f4` = 旋转、`f5` = 恒 1（[A][R][J]，2026-10-15 更正：`f2` 为生效范围而非强度）。
- **两个 oneof 变体字段差**（[R][A]）：

| 变体 | 字段 | 说明 |
|---|---|---|
| **f51** | `{f2:f32(半径), f3:f32(强度), f4:uint颜色}` | **2 个 float**（[J]，2026-10-15 更正：`f2`=半径、`f3`=强度；**不含 `f1`**） |
| **f52** | `{f2:f32(半径), f3:f32(角度°), f4:f32(强度), f5:uint颜色}` | **3 个 float**（颜色字段后移一位）（[J]，2026-10-15 更正：`f2`=半径、`f3`=角度、`f4`=强度） |

- **聚光灯标志位 = 组件层的 `f1`**（**不是变体内部的字段**）：**带 `f1` ⇔ 聚光灯；不带 ⇔ 点光源**（[A] 全档 **695 盏零例外**）。此前两版表格把 `f1:enum` 误列进了两个变体内部，**2026-10-15 已更正**。

- 颜色字段是组件里**唯一保留可读的成员名**（印证颜色位）。（[R]）
- **点 / 聚光灯归属 = 已定案（[J] 人工核验，2026-10-15）**：`f51` = **点光源**、`f52` = **聚光灯**。此前两说并列——卡片 / 用户口径曾称 `f51`=聚光灯、`f52`=点光源，字节结构口径反着指（`f52` 比 `f51` 恰多一个 float，最像聚光灯专属的「锥角 / 角度」，UI 亦有聚光灯专属键「角度」）。用户以一件 A/B 对照件（两件只差光源变体一个字段）在实机目视判别定案：**卡片口径被否，字节层结构推理方向被证实**。
- 反编译侧光照类型枚举成员名**全部被剥空** → 无法从代码判定点 / 聚光灯（[R]）。

### 14.2 实体光照组（实体 `f7` 槽 `cid=38` → 载荷 `f49`）

```
实体.f7 槽 { f1:38, f2:1,
  f49 {
    f1 {                        # 光照组容器
      f1:1 f2:1 f3:1
      f501 (repeated 具名灯) {
        f2: '光源1'             # 灯名
        f4: { <光源组件> }       # ★与 14.1 同一光组件结构
        f5: 1
        f6: 'GI_RootNode'       # 挂接点
      }
      f502: 1
    }
  } }
```
- 具名灯字段（[A][R]）：`f2` 灯名 / `f3` 未定 / `f4` **光组件** / `f5` 序号 / `f6` **挂接点**（默认根节点）。
- **`tc=27` 资产与实体光照组共用同一光组件结构**（`f51` oneof 一模一样），差别只在**外层壳**。（[A]；旧假设「两套平行系统」已废）
- 官方（[D]）：实体/元件编辑 → 组件页签 → 加「光源」→ 详细编辑；**一个光源组件可同时生效多盏灯**；参数含 初始生效 / 光源序号（不可改）/ 光源名称 / 光源类型（点光源、聚光灯）/ 颜色 / 半径 / 强度 / 生效范围（用于性能优化）/ 挂接点 / 位置 / 旋转。
- **光源必须偏出宿主几何之外，否则不发光**（[J]，用户实测）——灯要与被照对象的几何离开。
- 相关节点：**开关实体光源**（按「光源序号」控制开关，见 07 篇）。
- **待核**（§13 未定族）：`f501.f5`（=3）是「类型」还是「序号」**未锚**。~~`f4.f3` 是「半径」还是「偏移」、`f4.f4` 是「旋转」还是「颜色」~~ → **已定案（[J] 2026-10-15）**：`f4.f3` = 位置（相对挂接点偏移 vec3）、`f4.f4` = 旋转 vec3。
